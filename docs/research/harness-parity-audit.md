## Gap table


Areas group the rows:

- `lifecycle`: install, update, adopt, repair, uninstall, and doctor on an existing `next` install.
- `verbs`: the daily `atomic` verbs a Claude user runs.
- `artifacts`: the text of installed agents, commands, skills, and steering.
- `claude`: how Claude Code consumes what the branch writes, and what the branch reports about Claude.
- `omp`, `codex`: delivery to that harness. The `next` column states what a Claude user has on `next`, which is the bar for the other harness.

Statuses:

- `open`: a gap that no decision covers.
- `redesign`: taken by the 2026-10-21 redesign (harness-neutral `.atomic/` state root, `ATOMIC_HARNESS`, `.pi`, and `harness.dir` retired, per-harness agent overrides with native agent delivery, session-start carriers on OMP and Codex, reminders removed, workflow preferences). The audit ran before the redesign; CP16 re-runs each `redesign` row and replaces its status with what it observed.
- `closed`: fixed on the branch, with a regression test that fails if the gap returns.
- `accepted`: declared in the PR body and accepted by the owner (removal of agent `tools:` pins, doctor growing to 24 categories, additive verbs).

The parenthesis after a status names the checkpoint in `docs/spec/omp-plugin-compatibility.md` that closes the row. `probe-gated` means the row depends on a capability no runtime probe has proven: the checkpoint delivers it once the probe passes and reports it `unsupported` until then.

Evidence paths are repo-relative. A path with no line number means the audit recorded the file only. Tags: `run` is reproduced by running the binaries in a sandbox, `src` is read from source and not executed, `doc` is vendor documentation and not executed.

- CI skips every real-launch proof because the binaries and credentials are absent.
