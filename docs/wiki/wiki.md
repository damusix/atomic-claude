# wiki

## What it does

Maintains a cross-repository knowledge base (the "wiki") for one realm of repos. Deterministic CLI verbs (`atomic wiki scan`, `atomic wiki stale`, `atomic wiki linkify`, `atomic wiki bucket`) scaffold, classify, fingerprint, and report freshness; `/refresh-wiki` drives the LLM pass — summarizing no-signals repos via `atomic-wiki-inferrer` in wiki-output mode, synthesizing cross-cutting concerns incrementally, and running a bucket-synthesis pass for each bucket with a non-empty diff (dispatching `atomic-wiki-inferrer` in bucket-synthesis mode, writing topic-keyed pages under `wiki/knowledge/`). A cheap session-start nudge and ship-time `.dirty` marker prevent unnoticed drift.

Bucket docs (`<bucket>/<slug>.md`, one topic per file) carry a six-key frontmatter contract (`title`, `type`, `description`, `tags`, `status`, `created`) that code indexes deterministically at two levels: a `<bucket-docs>` region in each bucket's own `index.md`, and a `<wiki-bucket-list>` region in the realm `wiki/index.md`. `atomic wiki scan` rebuilds both non-fatally as part of its existing pass; `atomic wiki bucket doc <bucket> <slug> [--router]` and `atomic wiki bucket skill <bucket>` scaffold a topic file and a per-bucket authoring skill; `atomic wiki bucket index [<bucket>]` forces a rebuild outside a scan.

## Artifacts

- [`commands/refresh-wiki.md`](../../commands/refresh-wiki.md) — `/refresh-wiki [root]` command: scan → stale → incremental LLM pass → bucket-synthesis phase → linkify → disposition report → `.dirty` clear → commit offer. Deterministic and judgment halves are fenced separately. On first run in a realm with no `<wiki-buckets>` block, prompts once for bucket names; blank response records `declined="true"` so the offer never re-fires. ## CLI code

- [`atomic/internal/wiki/wiki.go`](../../atomic/internal/wiki/wiki.go) — core package: `Scan(root, Options)` entry point. Stages: collision check → parse prior entries → `discoverMembers` (recursive walk from root's children, stops at each `.git` boundary, skips `node_modules`/`dist`/`build`/`target`/`vendor`/`.worktrees`/`tmp`/`.git` and the wiki dir itself, root never a member) → `classifyMembers` → scaffold → `writeWikiScanBlock` → `writeMembersSection` → `RebuildAllBucketIndexes` (non-fatal — a broken bucket region is reported to stderr but never blocks the scan). `Options.Clock` is injectable for deterministic test output.
- [`atomic/internal/wiki/wiki.go`](../../atomic/internal/wiki/wiki.go) (`classifyMembers`) — four-rule precedence per member: (1) prior `summarized` + summary file exists on disk → keep `summarized`; (2) [`docs/wiki/index.md`](index.md) exists → `indexed` (signals win over a leftover summary); (3) `discoverSummary` finds `wiki/repos/<name>.md` or `wiki/repos/<name>/` with at least one `.md` → `summarized`; (4) otherwise → `pending`. Rule 3 (disk-discovery) was added 2026-06-11 to make `summarized` reachable on a closing re-scan after `/refresh-wiki` writes summaries.
- [`atomic/internal/wiki/wiki.go`](../../atomic/internal/wiki/wiki.go) (`writeMembersSection`) — writes the `## Members` content into a `wiki-member-list` XML managed region in `wiki/index.md`, spliced through the shared `spliceManagedRegion` primitive ([`managedregion.go`](../../atomic/internal/wiki/managedregion.go)) rather than the legacy `<!-- wiki-members:start/end -->` HTML-comment markers. Before splicing, `migrateLegacyMemberMarkers` relocates any legacy-delimited region (heading included, when adjacent) onto an empty well-formed `wiki-member-list` region occupying the same position, so the first post-migration scan fills in cleanly with no duplicate heading. A stray unpaired legacy marker skips the members write entirely for that scan (left byte-for-byte untouched; a human resolves it by hand) rather than risking a half-migrated document. Link targets per status: `indexed` → `../<repo>/docs/wiki/index.md`; `summarized` → the recorded `SummaryPath` (`repos/<repo>.md` or `repos/<repo>/`); `pending` → `../<repo>/`.
- [`atomic/internal/wiki/wiki.go`](../../atomic/internal/wiki/wiki.go) (`buildMembersSection`) — produces the content for inside the `wiki-member-list` region (heading + listing, no markers of its own): OKF §6 listing form `- [name](target) - description` when a description is derivable via `DeriveMemberDescription`, or `- [name](target)` when no description can be found (link-only is valid per OKF §6 SHOULD semantics).
- [`atomic/internal/wiki/wiki.go`](../../atomic/internal/wiki/wiki.go) (`DeriveMemberDescription` / `deriveDescriptionFrom`) — `DeriveMemberDescription` reads a summary file and extracts a short one-line description via `deriveDescriptionFrom`, the shared ladder now factored out so [`bucketindex.go`](../../atomic/internal/wiki/bucketindex.go)'s `readTopicMeta` can reuse it against already-parsed frontmatter without a second file read. Resolution order: (1) frontmatter `description:` key — returned verbatim (trimmed); (2) first non-structural prose line from the body — skips blank lines, headings, blockquotes, HTML/tag lines, table rows, list items; for candidate lines reduces `[text](url)` to visible text, strips backtick inline-code and emphasis markers, collapses whitespace; rejects lines with ` | ` nav separator or fewer than 15 letter characters; (3) empty string when neither yields text. Result is always single-line, truncated to 120 characters. Missing/unreadable files return "".
- [`atomic/internal/wiki/managedregion.go`](../../atomic/internal/wiki/managedregion.go) — shared primitive for every code-generated region in a wiki markdown file: `spliceManagedRegion` idempotently replaces an XML-tag-delimited region (`<tag>…</tag>`) with fresh content, appending at EOF when the tag is absent and refusing (returning the document unchanged plus `errUnpairedRegion`) when exactly one of the open/close tags is present. `findLineAnchored`/`lastLineAnchored` match whole lines only. `renderManagedRegion` is the sole emitter of the mandatory blank line on each side of the content — CommonMark parses a tag alone on its own line as an HTML block that runs to the next blank line, so an unpadded listing renders as raw text instead of a list. `spliceRegionAt` is the tested primitive for placing a region at an interior document position (not just EOF-append), normalizing leading/trailing whitespace with a pad-if-missing/never-collapse rule; `migrateLegacyMemberMarkers` (wiki.go) is its first interior-placement caller. Backs both the bucket-doc index regions and the migrated `## Members` region.
- [`atomic/internal/wiki/bucketindex.go`](../../atomic/internal/wiki/bucketindex.go) — CP2 per-bucket topic index. `walkBucketTopics(bucketDir)` walks the bucket root plus one directory level — a deliberately different granularity than `bucket.go`'s per-file `WalkBucket` manifest walk (topics vs. staleness hashing answer different questions). A directory with a sibling `<slug>.md` collapses into that topic as a **router** (`Router: true`, `ChildCount` = recursive `.md` count); a directory with no sibling file is an **orphan** subtree entry instead. `readTopicMeta` fills `BucketTopic.Title`/`Description`/`Tags`/`Indexed` via three independent ladders: `deriveTitle` (frontmatter `title` → first H1 → filename stem), `deriveDescriptionFrom` (shared with `wiki.go`), `deriveTags` (frontmatter `tags` as a YAML string list; a bare string reads as one-element; any other malformed shape is ignored, not partially read). `hasRecognizedFrontmatterKey` checks the doc's frontmatter against `recognizedFrontmatterKeys` (`title`, `type`, `description`, `tags`, `status`, `created`) — no recognized key means `Indexed: false`, listed under `### Unindexed` rather than rejected. `listEntry` renders one topic as an OKF §6 line with description/tags/router-or-orphan suffixes. `RebuildBucketIndex(bucketDir)` splices the rendered listing into the bucket's own `<bucket-docs>` region. `renderBucketList`/`rebuildRealmBucketList` render and splice the realm `<wiki-bucket-list>` region in `wiki/index.md` from the `<wiki-buckets>` registry, marking a bucket whose directory is missing as link-only `(missing)` rather than erroring. `RebuildAllBucketIndexes(root, wikiDir)` rebuilds every registered bucket's region then the realm list, joining (not stopping on) any per-bucket failure so one broken bucket never blocks its siblings.
- [`atomic/internal/wiki/bucketdoc.go`](../../atomic/internal/wiki/bucketdoc.go) — CP4 scaffold verbs. `//go:embed templates/*.md` embeds three scaffold templates (`bucket-doc.md`, `bucket-router-claude.md`, `bucket-skill.md`) directly in the binary — like `doctemplate`'s skeletons, these are NOT install artifacts and are never mirrored into [`atomic/internal/embedded/bundle/`](../../atomic/internal/embedded/bundle). `validateSlug` enforces `[a-z0-9-]+` (same kebab-case discipline as knowledge topic names). `ScaffoldBucketDoc(bucketDir, slug, router, now)` refuses an existing `<slug>.md` (never overwrites), writes the doc with `created` stamped, and when `router` is true also calls `routerScaffold` to create the sibling `<slug>/` subtree + a [`CLAUDE.md`](../../CLAUDE.md) stub (both steps independent once the collision check passes; a pre-existing subtree never blocks the doc write). `ScaffoldBucketSkill(realmRoot, bucketName, bucketDir)` writes `<realmRoot>/.claude/skills/<bucketName>-management/SKILL.md`, pre-filled via `bucketPurposeLine` (reuses `DeriveMemberDescription` against the bucket's own `index.md`) — a pre-existing file is a silent no-op (path returned, nil error), not a refusal.
- [`atomic/internal/wiki/bucket.go`](../../atomic/internal/wiki/bucket.go) — CP1 bucket manifest core. `WalkBucket(dir)` returns sorted `<relpath>\t<sha256hex>` entries; excludes `index.md` at bucket root, [`.DS_Store`](../../.DS_Store)/`Thumbs.db`, and `skipDirs` subtrees. `RegisterBucket(wikiDir, name)` calls `validateBucketName` before creating `wiki/.buckets/<name>/` — rejects an empty/whitespace-only name, a name starting with `-`, a name containing a slash or backslash path separator, a name that is a single or double dot, or the reserved name `wiki` (issue #164 hardening, commit `08f596b`; a leading-dash name never reaches this path via the CLI, since `resolveWikiRoot` rejects it first — this is the register-time backstop for programmatic callers) — then refuses an already-registered name. `BucketDiff(wikiDir, name, dir)` walks dir, writes `wiki/.buckets/<name>/current`, diffs against baseline; all-added when no baseline exists (first call). `bucketDiffReadOnly` is the same diff without writing `current` — used by `list` (status verb, no side effects). `PromoteBucket(wikiDir, name, dir)` recomputes live walk; first promote: walk→baseline; subsequent: baseline→previous, walk→baseline.
- [`atomic/internal/wiki/bucket_registry.go`](../../atomic/internal/wiki/bucket_registry.go) — CP2 registry primitives. `spliceBucketEntry` maintains the `<wiki-buckets>` block in `wiki/index.md` — idempotent splice of `<bucket name="…" path="…"/>` entries; removes `declined="true"` attribute when a new bucket is added; creates the file if absent. `readBucketEntries` parses the block and returns `(name, path)` pairs. `writeCaptureSurfacesSection` appends a `## Capture surfaces` section to the realm [`CLAUDE.md`](../../CLAUDE.md) (written once on first `bucket add`; heading not duplicated; one bullet per bucket with `<!-- describe what this bucket is for -->` placeholder). `createBucketIndexStub` writes `<bucketDir>/index.md` if absent — now with OKF frontmatter (`title`, `type: Bucket`, `description` placeholder), an H1, a `## Conventions` placeholder, and an empty `<bucket-docs>` region already in place, so the first `RebuildBucketIndex` fills an existing well-formed region instead of appending a fresh one at EOF; no-op if the file already exists.
- [`atomic/internal/wiki/action.go`](../../atomic/internal/wiki/action.go) — `WikiAction` / `wikiAction` — exported/unexported testable seam for `atomic wiki` subcommand dispatch. Switch on verb: `scan`, `stale`, `stamp`, `mark-dirty`, `linkify`, `bucket`. `wikiBucketAction` sub-dispatches `add`, `list`, `diff`, `promote`, `doc`, `skill`, `index`. `resolveRegisteredBucket(indexPath, name)` is the shared lookup the three new verbs use to resolve a bucket name against the `<wiki-buckets>` registry, erroring with the sorted list of registered names when the lookup fails. `wikiBucketDocAction` parses `--root`/`--router` (via `parseBucketDocArgs`) plus `<bucket> <slug>` positionals and calls `ScaffoldBucketDoc`. `wikiBucketSkillAction` calls `ScaffoldBucketSkill`, stat'ing the target beforehand to print `already exists: <path>` vs. the bare path plus a "loads at the realm root" note. `wikiBucketIndexAction` with no bucket arg calls `RebuildAllBucketIndexes` directly; with a bucket arg it rebuilds just that bucket via `RebuildBucketIndex` then refreshes only the realm list via `rebuildRealmBucketList` — no re-walk of sibling buckets. `wikiStampAction` dispatches three modes: summary (`--repo`), concern (`--root` + `--cites`), knowledge (`--knowledge` + `--sources`). Knowledge topic names must match `[a-z0-9][a-z0-9-]*\.md`; non-conforming names are skipped with exit 0.
- [`atomic/internal/wiki/action.go`](../../atomic/internal/wiki/action.go) (`resolveWikiRoot`, `errUsageRequested`, `parseBucketDocArgs`) — issue #164 hardening (commit `08f596b`): `resolveWikiRoot` is the shared `--root`-plus-positionals scanner behind every `wiki bucket` verb. It recognizes `-h`/`-help`/`--help` in any argument position and returns the sentinel `errUsageRequested` (mirrors stdlib `flag.ErrHelp`; callers check with `errors.Is`); any OTHER dash-prefixed token, single- or double-dash, is rejected with an error instead of falling through to the positional list — before this fix only `--`-prefixed unknowns were rejected, so `atomic wiki bucket add -h` fell through and registered a bucket literally named `-h`. All seven bucket actions (`add`, `list`, `diff`, `promote`, `doc`, `skill`, `index`) answer the sentinel by printing their own usage string to `out` and returning exit 0 — no filesystem write. `parseBucketDocArgs` (the `doc` verb's arg parser) was a second, near-duplicate hand-rolled scanner before this fix; it is now a thin wrapper that consumes `--router` and delegates everything else to `resolveWikiRoot`, so flag/help classification has exactly one implementation.
- [`atomic/cmd/atomic/main.go`](../../atomic/cmd/atomic/main.go) (`buildWikiCmd`) — registers `stamp <file>` via `addSub` with flags `--repo`/`--root`/`--cites`/`--knowledge`/`--sources`; the parent `wiki` command's `Short` text lists `scan|stale|linkify|bucket|init|stamp`. The `bucket` intermediate command's `Short` text now reads `Manage capture buckets (add|list|diff|promote|doc|skill|index)`. `addBucketSub` takes an optional `flagFn` so `doc` can register its own `--router` bool flag alongside the shared `--root`; `skill` and `index` reuse the shared flag set unmodified.
- [`atomic/internal/cliusage/cliusage.go`](../../atomic/internal/cliusage/cliusage.go) — `wiki stamp` `Command` entry: `Path: ["wiki", "stamp"]`, `Args: "<file>"`, `Flags: ["--repo", "--root", "--cites", "--knowledge", "--sources"]`. Makes `wiki stamp` visible to `atomic wiki --help` and to the A1 citation lint (`validate/artifacts.go`). Three new entries mirror this pattern: `wiki bucket doc` (`Args: "<bucket> <slug>"`, `Flags: ["--root", "--router"]`), `wiki bucket skill` (`Args: "<bucket>"`, `Flags: ["--root"]`), `wiki bucket index` (`Args: "[<bucket>]"`, `Flags: ["--root"]`) — same doctor-domain coordination hazard as every other `wiki` verb: a `main.go` registration without a matching `cliusage.go` entry desyncs `--help` output from the A1 lint.
- [`atomic/internal/wiki/stale.go`](../../atomic/internal/wiki/stale.go) — `Stale(root, out)` entry point for `atomic wiki stale`. Three check sections: (1) membership/status drift against `<wiki-scan>` block; (2) per-artifact content drift — 2a resolves each `repos/*.md` summary to its owning `Member` via `resolveSummaryMember` (see below) and compares `reflects_rev` to that member's git HEAD, 2b compares concern `reflects:` entries vs recomputed fingerprints; (3) bucket staleness — reads `<wiki-buckets>` block, calls `bucketDiffReadOnly` per entry, emits `STALE bucket <name>` when diff non-empty. Walk/I/O errors on buckets escalate to exit 2. DRIFT/STALE repo/concern/summary lines are sorted first; bucket lines sorted after. Exit 0=fresh, 1=stale, 2=hard error.
- [`atomic/internal/wiki/stale.go`](../../atomic/internal/wiki/stale.go) (`resolveSummaryMember` / `summaryStem`) — resolves a `repos/*.md` summary file's wiki-relative path to its owning `Member.Path` for Stale's 2a section, fixing GitHub issue #157: the prior derivation reconstructed the member directory by `SplitN`-splitting the summary path under `wiki/repos/`, which never stripped `.md` for flat summaries and discarded the parent path for nested members, leaving the `reflects_rev` comparison unreachable for 3 of the 4 member-location × summary-layout shapes. Three-step order: (1) claimed match — a member whose `SummaryPath` equals the summary's wikiDir-relative path (flat form) or is its trailing-slash-anchored directory prefix (split form); (2) base-name fallback — exactly one member whose `filepath.Base(Path)` equals the stem `summaryStem` extracts from `repos/<name>.md` or `repos/<name>/<domain>.md`, needed because `classifyMembers` rule 2 (`indexed`) outranks rule 3 (`summarized`), leaving a graduated member's `SummaryPath` empty even when its summary file is still on disk; (3) unresolved (no claim, zero or ambiguous base-name matches) → `STALE summary` fail-safe. `repoDir` for the `reflects_rev`/`gitRevParseHead` comparison is then `filepath.Join(root, member.Path)`, not a path reconstructed from the summary file's own location.
- [`atomic/internal/wiki/stamp.go`](../../atomic/internal/wiki/stamp.go) — `StampSummary` writes `reflects_rev` from `git rev-parse HEAD`; `StampConcern` writes `reflects:` YAML list (each entry `<id>@<fp>`); `StampKnowledge` writes `sources:` YAML list — caller supplies `"<bucket>/<relpath>@<sha256hex>"` entries verbatim, code writes them. `resolveFingerprint` handles three id types: `knowledge/<topic>.md` → sha256 of `wiki/knowledge/<topic>.md` content; indexed repo → sha256 of `signals.md` content; summarized repo → git HEAD SHA. Unresolvable id silently skipped.

## Coupling

- **signals domain** — `atomic signals scan --out <dir>` redirect is a direct dependency of wiki-output mode; changes to that flag's behavior or output format propagate to the no-signals summarization path. The `signals-gate` partial (composed by all ship verbs) calls `atomic wiki mark-dirty` after signals refresh — adding a ship verb without signals-gate breaks the drift marker.
- **signals domain** — `atomic-wiki-inferrer` is dispatched in wiki-output mode by `/refresh-wiki`; the agent's prompt contract (both `target_repo` + `wiki_dir` required, fail loud on partial args) is a cross-domain dependency. The agent is also dispatched in bucket-synthesis mode per bucket with a non-empty diff; that mode writes pages under `wiki/knowledge/`.
- **config domain** — `wiki.CheckStaleness` reads `<wikis>` from `~/.claude/CLAUDE.md`; `atomic claude install` also writes to that file. Changes to the `<wikis>` block format require coordinated updates in both. The `claude-merge` cold-op brief ([`atomic/internal/coldprompt/briefs/claude-merge.md`](../../atomic/internal/coldprompt/briefs/claude-merge.md)) preserves the `<wikis>` block verbatim on merge. `bucket add` writes a `## Capture surfaces` section to the realm [`CLAUDE.md`](../../CLAUDE.md) — a separate file from `~/.claude/CLAUDE.md`.
- **bundle domain** — [`commands/refresh-wiki.md`](../../commands/refresh-wiki.md) and [`agents/atomic-wiki-inferrer.md`](../../agents/atomic-wiki-inferrer.md) are rendered artifacts; touching their templates requires `make render` + `make bundle`. The wiki Go package is part of the embedded binary. The three `atomic/internal/wiki/templates/*.md` scaffold templates are a SEPARATE embed (`//go:embed templates/*.md` in [`bucketdoc.go`](../../atomic/internal/wiki/bucketdoc.go)) — compiled into the binary but never mirrored into [`atomic/internal/embedded/bundle/`](../../atomic/internal/embedded/bundle) and never installed to a user's `~/.claude`; do not confuse them with bundle domain's rendered command/agent/skill artifacts.
- **workflow domain** — `/refresh-wiki` invokes `atomic-git-discipline` skill for the commit message offer; wiki commit is offered, never automatic (axiom 3).
- **doctor domain** — [`atomic/internal/cliusage/cliusage.go`](../../atomic/internal/cliusage/cliusage.go) is doctor domain's CLI-surface single source of truth; the `wiki stamp` `Command` entry there is what makes the verb visible to `atomic wiki --help` and to doctor's A1 citation lint (`validate/artifacts.go`). Registering or removing a `wiki` verb in [`atomic/cmd/atomic/main.go`](../../atomic/cmd/atomic/main.go) without a matching `cliusage.go` entry desyncs the two — now three more verbs (`bucket doc`/`skill`/`index`) carry this same hazard.

## Conventions worth knowing

- `classifyMembers` rule 3 (disk-discovery) makes `summarized` reachable on first derivation. Before the 2026-06-11 amendment, `summarized` was unreachable without a prior index entry — nothing ever wrote the status initially. The fix: after `/refresh-wiki` writes summaries, the closing re-scan calls `discoverSummary` and picks them up.
- `discoverSummary` looks for `wiki/repos/<name>.md` (single-file form) or `wiki/repos/<name>/` containing at least one `.md` (domain-split form). `<name>` is `filepath.Base(rel)`. Domain-split summary path stored as `repos/<name>/` (trailing slash).
- `buildMembersSection` emits OKF §6 listing form. `DeriveMemberDescription` is called for each member whose summary file is known; when it returns a non-empty string the line is `- [name](target) - description`; when it returns empty the line is `- [name](target)` (link-only is valid per OKF §6 SHOULD semantics). `DeriveMemberDescription` is exported and takes a summary file path.
- Fingerprints are always written by code (`atomic wiki stamp`), never the model. For knowledge pages: the model supplies which bucket files contributed (`--sources`); code writes every SHA-256 value. For concerns: model declares cited repo ids (`--cites`); code resolves and writes each fingerprint.
- `<wiki-scan>` block carries `root` and `generated` (date from injected clock) on the open tag. Membership and status only — no fingerprints in the block. `generated` doubles as the neglect baseline read by `wiki.CheckStaleness`.
- `<wiki-buckets>` block in `wiki/index.md` carries `<bucket name="…" path="…"/>` entries. `declined="true"` attribute on the open tag means the user declined the bucket-add offer; the block exists but has no entries. `spliceBucketEntry` removes the attribute when a real bucket is added.
- Bucket manifests live at `wiki/.buckets/<name>/` with three files: `current` (debugging artifact, never read back as state), `baseline` (what `diff` compares against), `previous` (prior baseline). `PromoteBucket` always recomputes the walk live — never reads a previously written `current` file.
- `bucketDiffReadOnly` (used by `list` and `stale`) never writes `current`. `BucketDiff` (used by `diff` verb) writes `current`. This is intentional: `list` and `stale` are status verbs with no side effects.
- `atomic wiki mark-dirty` is the sole internal-only `wiki` verb. `atomic wiki stamp` is a registered public subcommand (visible in `atomic wiki --help` and to the A1 citation lint) but is still called only by `/refresh-wiki` and the atomic-wiki realm pipeline, not typed by users directly. `atomic wiki linkify` and `atomic wiki scan`/`stale` are user-facing and surfaced in `/atomic-help`. `bucket add/list/diff/promote/doc/skill/index` are all user-facing.
- Session-start staleness nudge threshold defaults to 30 days (memory, axiom 2 — conversational nudge, not config).
- `atomic wiki scan` is idempotent: re-running regenerates only the `<wiki-scan>` block, the `wiki-member-list` region, and both bucket-doc index regions (`<bucket-docs>` per bucket, `<wiki-bucket-list>` realm-wide); content outside those managed zones and all files under `repos/`/`concerns/`/`knowledge/` are untouched.
- Root collision: if `wiki/` exists but `index.md` is absent or lacks a `<wiki-scan>` marker, `scan` refuses with a non-zero exit and names the path in the error.
- Knowledge topic filenames must match `[a-z0-9][a-z0-9-]*\.md` (kebab-case). Non-conforming names are rejected by `wikiStampAction` with exit 0 (skip, not error). Bucket-doc slugs match `[a-z0-9-]+` (`validateSlug`, `bucketdoc.go`) and are rejected with a hard error, not a silent skip, on mismatch.
- Concern files may cite knowledge pages as `knowledge/<topic>.md` in `--cites`; `resolveFingerprint` computes sha256 of the knowledge page file content (not a git revision). `StampConcern`'s resolution uses `wikiDir` as root for knowledge-page ids and `realmRoot` for repo ids.
- XML managed-region tags (`<tag>…</tag>`, `managedregion.go`) are the current mechanism for every code-generated splice in a wiki markdown file — heading-bounded splicing (the legacy `## Members` approach) can't distinguish "the next heading" from a heading a user typed inside the generated section. A blank line on each side of a region's content is mandatory, not cosmetic: CommonMark parses a tag alone on its own line as the start of an HTML block that runs to the next blank line, so unpadded content renders as raw text. `renderManagedRegion` is the only emitter of that padding.
- A region-splice that finds exactly one of the open/close tags (`regionUnpaired`) never truncates the document — it returns the error and the document byte-for-byte unchanged. Every call site (bucket index rebuild, realm bucket list, the legacy-marker migration) surfaces this as a non-fatal warning and continues, matching `Scan`'s established "warn to stderr, keep going" pattern.
- `ScaffoldBucketDoc` (hard refusal on collision) and `ScaffoldBucketSkill` (silent no-op on collision) deliberately differ in failure shape: a doc-slug collision likely signals a topic-naming mistake worth surfacing to the caller, while a skill-file collision is the expected, harmless outcome of re-running the scaffold on a realm that already has it.
- `createBucketIndexStub`'s scaffolded `index.md` and the templates in [`atomic/internal/wiki/templates/`](../../atomic/internal/wiki/templates) are two independent seams: the stub is written directly by Go string-building in `bucket_registry.go`; the three scaffold docs (`bucket-doc.md`, `bucket-router-claude.md`, `bucket-skill.md`) are `//go:embed`-ed markdown files with `{{PLACEHOLDER}}` tokens replaced by `strings.NewReplacer`/`strings.ReplaceAll`. Neither reuses the other's rendering path.
- `resolveWikiRoot` is the single scanner behind every `wiki bucket` verb's arg parsing (issue #164). Before this fix, `parseBucketDocArgs` was a second, near-duplicate hand-rolled scanner — the duplication is why the `-h`-becomes-a-bucket-name defect had two sites to fix instead of one. A help probe (`-h`/`-help`/`--help`, any position) always exits 0 with usage printed to `out` and no filesystem write; any other dash-prefixed token, single- or double-dash, is a hard reject (exit 2) rather than a silent fall-through to positional — a bucket name can never begin with `-`.
