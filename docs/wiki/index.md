- **Go 1.25**, single module at [`atomic/go.mod`](../../atomic/go.mod) (`module github.com/damusix/atomic-claude/atomic`). CLI binary named [`atomic`](../../atomic).

- **VitePress docs site**: [`package.json`](../../package.json) (`name=atomic-claude-docs`), [`package-lock.json`](../../package-lock.json), [`.vitepress/config.mts`](../../.vitepress/config.mts). - No web framework. SQLite used only by the code-intel engine at `<projectRoot>/.claude/.atomic-index/atomic.db`.

## Build / test / lint

All commands run from [`atomic/`](../../atomic) (CI: `working-directory: ./atomic`):

| Purpose | Command | Source |
|---------|---------|--------|
| Render command templates | `make render` (root) or `make -C atomic render` | [`atomic/Makefile`](../../atomic/Makefile), CI "Verify render is committed" |
| Regenerate embedded bundle | `go generate ./...` → `make -C atomic bundle` | [`atomic/Makefile`](../../atomic/Makefile) target `bundle`, CI "Verify bundle is committed" |
| Run tests | `go test ./...` | [`atomic/Makefile`](../../atomic/Makefile) target `test` |
| Vet | `go vet ./...` | [`atomic/Makefile`](../../atomic/Makefile) target `vet` |
| Format check | `gofmt -l .` | [`atomic/Makefile`](../../atomic/Makefile) target `fmt` |
| Build binary | `go build -o ../bin/atomic ./cmd/atomic` | [`atomic/Makefile`](../../atomic/Makefile) target `build` |
| Tidy deps | `go mod tidy` | [`atomic/Makefile`](../../atomic/Makefile) target `tidy` |
| Release | `goreleaser release --clean` | [`.github/workflows/release.yml`](../../.github/workflows/release.yml) (on `v*` tag) |

CI gates: (1) `make render && git diff --exit-code` — stale [`commands/`](../../commands) fails. (2) `make bundle && git diff --exit-code` — stale `manifest.go` fails. Pipeline order: render must run before bundle.

Passing `~/.claude` caused `hooks.IsInstalled` to look for `~/.claude/.claude/settings.json` (double [`.claude`](..) segment). `RunCheckHooksWith(scopeRoot)` is exported for tests; `checks_hooks_internal_test.go` added for package-internal test coverage.

**`go:embed all:bundle` requirement (bundle)**: [`commands/_templates/`](../../commands/_templates) starts with `_` — excluded by the default embed glob. `all:bundle` overrides this. Any new underscore-prefixed directory under `embedded/bundle/` needs this same consideration.

**Pipeline order is load-bearing (bundle)**: `make render` must precede `make bundle`. The pre-commit hook stages 1 and 2 enforce this order; stage 1 re-stages both [`commands/`](../../commands) and [`agents/`](../../agents) after render. CI runs the same two drift gates in order. Running only `make bundle` after editing a template embeds stale command or agent outputs.

**Agent template partial pipeline**: [`templates/agents/`](../../templates/agents) now mirrors [`templates/commands/`](../../templates/commands) — agent source files are rendered, not directly edited. Editing `agents/*.md` directly is overwritten on next render — edit `templates/agents/*.md` instead.

**Signals refresh timing (spec: [`docs/spec/signals-refresh-timing.md`](../../docs/spec/signals-refresh-timing.md))**: the implementation phase owns the primary refresh. `/subagent-implementation` Phase 3 finalize and `/autopilot` Phase 4 each dispatch `atomic-wiki-inferrer` with `mode: silent`, `first_run: false`, and `changed_range: <loop-base>..HEAD` (HEAD after docs commits); committed as `chore(signals): refresh after <topic>`. Ship verbs are the ad-hoc fallback: the `signals-gate` partial (1) checks the staged set with `git diff --cached --name-only` — if non-empty and entirely documentation paths, skips entirely; empty staged set falls through to the staleness check; (2) runs `atomic signals stale` — exit 0 (fresh, including "impl phase already refreshed") → skip; exit 1 → dispatch; exit 2 → report + skip. **`atomic validate artifacts` (rule A1, doctor domain)**: [`atomic/internal/cliusage/`](../../atomic/internal/cliusage) is the single source of truth for the [`atomic`](../../atomic) command surface — verb-path tokens, accepted `--flags`, descriptions. `main.go` renders `--help` from it; `validate/artifacts.go` uses it to lint artifact citations for unknown verbs/flags. Adding or removing a verb or flag requires updating `cliusage.go`; failing to do so causes `atomic validate artifacts` to either false-positive (flag a valid citation) or false-negative (miss an invalid one). The A1 rule fires as part of whole-repo `atomic validate` (no subcommand) and as `atomic validate artifacts [paths...]`. The `atomic-verify` skill integration spec is at [`docs/spec/verify-gate-validate.md`](../../docs/spec/verify-gate-validate.md).
