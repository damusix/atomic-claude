# config

## What it does

User config, state directory, session hooks, reminders, follow-ups, and git state management. Everything that persists user preferences or project-local operational state across sessions. [`atomic/internal/config`](../../atomic/internal/config) owns the TOML schema; [`atomic/internal/followups`](../../atomic/internal/followups) owns the per-entry folder; [`atomic/internal/hooks`](../../atomic/internal/hooks) installs the session-start hook. Cold-op briefs for git cleanup and CLAUDE.md merge are embedded in the binary via [`atomic/internal/coldprompt`](../../atomic/internal/coldprompt) — they are NOT install artifacts and are never written to `~/.claude`. Per-user state root is `~/.atomic/` (GitHub issue #150, v6 breaking change — moved from `~/.claude/.atomic/`; see the state-directory-layout table below and [`docs/spec/configurable-state-paths.md`](../spec/configurable-state-paths.md)). Repo-local state paths — `.scratchpad/`, `project/` (followups), `.atomic-index/`, `atomic.toml`, `worktrees/` — resolve through one config key, `harness.dir` (string, default [`.claude`](../../.claude)), read once per process by [`atomic/internal/config/harness.go`](../../atomic/internal/config/harness.go)'s `harnessDir()` resolver; `atomic config set harness.dir .pi` repoints every repo-local helper to `.pi/...`. [`atomic/internal/config/repo.go`](../../atomic/internal/config/repo.go) owns a second, repo-scoped schema — `<projectRoot>/<harness.dir>/atomic.toml` (default `<projectRoot>/.claude/atomic.toml`), resolved via `config.RepoConfigPath` (harness.go) — distinct from the user-scoped `~/.atomic/config.toml` above: it is committed to the repo and currently holds only `[code] ignore` glob patterns consumed by the code-intel indexer (code-intel domain). This domain also owns repo-local [`.claude/`](../../.claude) layout scaffolding — [`.claude/.scratchpad/`](../../.claude/.scratchpad), [`.claude/project/`](../../.claude/project), [`.claude/worktrees/`](../../.claude), and the gitignore rules that keep them (plus root `tmp/`) out of version control — via the `atomic repo init` verb, implemented in [`atomic/internal/repoinit`](../../atomic/internal/repoinit) (all four repo-local paths now derive from the same `harness.go` helpers rather than hardcoded literals).

## Artifacts

**Follow-ups and git state:**

- [`commands/follow-up.md`](../../commands/follow-up.md) — `/follow-up [due <id> | review]`. Reviews pending follow-ups. `/follow-up review` triages stale [`.claude/project/followups/`](../followups) entries with per-item `extend|close|promote|skip`.
- [`commands/git-cleanup.md`](../../commands/git-cleanup.md) — `/git-cleanup [<name>]` runs `atomic prompt git-cleanup` via a `general-purpose` subagent (no `subagent_type`; read-only scan only). Presents indexed report; confirms before deleting anything. Plain-text indexed selection (axiom 4).

**Reminders and scheduling:**

- [`commands/remind-me.md`](../../commands/remind-me.md) — `/remind-me <duration> <text>` schedules reminder via cron. Degrades to file-only without `CronCreate`.
- [`commands/watch-ci.md`](../../commands/watch-ci.md) — `/watch-ci` dispatches `general-purpose` with `model: haiku` as a background subagent to watch CI. Provider auto-detected from signals or file-tree heuristics.

## CLI code

Briefs are embedded in the binary at build time and are NOT part of the install bundle shipped to `~/.claude`.
- [`atomic/internal/doctemplate/doctemplate.go`](../../atomic/internal/doctemplate/doctemplate.go) — mirrors `coldprompt`: `//go:embed templates/*.md` into `templatesFS embed.FS`, holding 8 fill-in skeletons for the documents the workflow coordinates (design doc, spec, scratchpad brief/state/followups, session report, diagnose context, implementation log): `brief.md`, `design-doc.md`, `diagnose-context.md`, `followups.md`, `implementation-log.md`, `session-report.md`, `spec.md`, `state.md`. The `atomic template <name>` binary verb prints the skeleton to stdout. Skeletons are embedded in the binary at build time and are NOT install artifacts — never shipped to `~/.claude`, so Claude Code surfaces no new command/skill entries.
- [`atomic/internal/coldprompt/briefs/git-cleanup.md`](../../atomic/internal/coldprompt/briefs/git-cleanup.md) — self-contained brief for a `general-purpose` subagent performing the read-only git state scan. Replaces the former `atomic-git-scout` agent.
- [`atomic/internal/coldprompt/briefs/claude-merge.md`](../../atomic/internal/coldprompt/briefs/claude-merge.md) — self-contained brief for a `general-purpose` subagent merging `~/.atomic/proposed/CLAUDE.md` into `~/.claude/CLAUDE.md`. Replaces the former `atomic-claude-merger` agent. Preserves `<wikis>` block verbatim on merge.
- [`atomic/internal/config/config.go`](../../atomic/internal/config/config.go) — TOML-backed user config. Load/validate/persist. v1 schema: `output.signals.max_depth` (int, default 3), `update.run_doctor` (bool, default `true`), `harness.dir` (string, default [`.claude`](../../.claude) — see `harnessDirDefault`). `output.intensity` was removed — the schema no longer contains it. Atomic write via `os.Rename`. Levenshtein typo-suggestion on unknown key names. Raw-map presence check distinguishes absent `update.run_doctor` (default `true`) from explicit `false`. `validateHarnessDir` rejects empty, [`.`](../..), [`..`](../../..), and any value containing [`/`](../..) on `Set`; `Load` re-applies the same check leniently (falls back to the default rather than erroring) so a hand-edited invalid value never reaches `filepath.Join` in the repo-local helpers.
- [`atomic/internal/config/cli.go`](../../atomic/internal/config/cli.go) — `atomic config get|set|unset|list|path` subcommand dispatch.
- [`atomic/internal/config/paths.go`](../../atomic/internal/config/paths.go) — canonical user-state path functions: `Dir(home)` → `<home>/.atomic`, `TOMLPath`, `ResolvedPath`, `BackupDir`, `ProposedCLAUDEMD`, `ProfilePath`, `ProfileRelPath`. Single source of truth for all `~/.atomic/` path derivation; the `claudeHome` parameter was renamed `home` throughout (issue #150 — the root no longer nests under [`.claude`](../../.claude)). `ProfilePath(home)` returns the disk path to `~/.atomic/profile.md`; `ProfileRelPath()` returns the home-relative constant `.atomic/profile.md`.
- [`atomic/internal/config/harness.go`](../../atomic/internal/config/harness.go) — repo-local path resolver (issue #150). `harnessDir()` resolves `harness.dir` once per process (`sync.Once`) from `~/.atomic/config.toml` via `resolveHarnessDirFromHome(home)`, lenient on any load/validation error (falls back to [`.claude`](../../.claude)); `SetHarnessDirForTest(dir)` is the test seam, returning a restore func. Eight repo-local helpers join `root + harnessDir() + suffix`: `ScratchpadDir`, `ProjectDir`, `FollowupsDir` (`ProjectDir/followups`), `IndexDir`, `IndexDBPath` (`IndexDir/atomic.db`), `WorktreesDir`, `RepoConfigPath` (`<root>/<harness.dir>/atomic.toml`), `RemindersDir` (`ScratchpadDir/reminders`). Consumer packages (reminder, followups, codeintel engine/mcp/realm/cli, repoinit, signals tree, doctor followups/repo-config checks, docs, serve) call these instead of holding private path constants.
- [`atomic/internal/config/statemigrate.go`](../../atomic/internal/config/statemigrate.go) — `MigrateUserState(home)`: moves legacy `<home>/.claude/.atomic` to `<home>/.atomic` (issue #150), idempotent (no-op once `<home>/.atomic` is a real dir) and never merges a still-real legacy dir into an existing new one. Same-filesystem `os.Rename`; on `EXDEV` or other rename failure, falls back to a recursive copy staged into a sibling `.atomic.migrating` dir and renamed into place atomically, so a partial copy never occupies `~/.atomic`. Leaves a compat symlink `<home>/.claude/.atomic → <home>/.atomic` (via `ensureCompatSymlink`) so pre-v6 `@~/.claude/.atomic/...` refs in installed CLAUDE.md files keep resolving; the symlink is (re-)ensured even when `~/.atomic` already exists, so a prior run's failed symlink step is retried on the next invocation. Never calls `os.UserHomeDir` — takes `home` as a parameter so tests use a temp dir.
- [`atomic/internal/config/render.go`](../../atomic/internal/config/render.go) — renders resolved config values, including `harness.dir`, to `~/.atomic/config.resolved.md` (the markdown snapshot `@`-ref'd from bundled [`CLAUDE.md`](../../CLAUDE.md)).
- [`atomic/internal/config/repo.go`](../../atomic/internal/config/repo.go) — repo-scoped config parsing: `LoadRepoConfig(path)` (path now supplied by `harness.go`'s `RepoConfigPath(root)`, not a local const) into `RepoConfig{Code.Ignore []string}`. Same lenient-load contract as `config.go`'s `Load`: missing file → empty config, no error; unknown keys → `Warning`, no error; malformed TOML → error the caller degrades on. `NewIgnoreMatcher(patterns)` builds an `IgnoreMatcher`: a pattern containing a slash character is a doublestar full-path match against repo-relative slash paths (`fullPath` field); a pattern without a slash matches the basename at any depth (`basenames` field); a leading dot-slash prefix is stripped; a trailing-slash-only pattern matches nothing; an invalid pattern (per `doublestar.ValidatePattern`) is dropped with a `Warning`, never panics; no negation syntax. `Match(relPath)` uses `doublestar.MatchUnvalidated` — patterns are pre-validated at construction, so re-validating per call is redundant. `PatternCount()` returns the number of active patterns, used by `atomic code status`. Depends on the `github.com/bmatcuk/doublestar/v4` module.
- [`atomic/internal/hooks/hooks.go`](../../atomic/internal/hooks/hooks.go) + `hooks_hujson.go` — session-start hook payload generation and install/uninstall. `Install` registers the inline command `atomic hooks session-start` directly in `settings.json`'s `SessionStart` hook entry — no wrapper script written to disk. `Uninstall` removes both the inline registration and any lingering legacy script. `IsInstalled(scopeRoot)` returns `(installed, drifted, err)`: `drifted=true` when a legacy wrapper-script registration is detected (functional but should be migrated). `migrateLegacy` removes the legacy `~/.claude/hooks/session-start-reminders.sh` registration and file on fresh `Install` calls. `legacyScriptName` / `legacyHooksSubdir` constants retained for migration and cleanup only. `hooks_hujson.go` uses `github.com/tailscale/hujson` for lenient JSON parsing of `settings.json`. `refreshProfile`'s session-start ride-along resolves `profile.md` from `home` (the `~/.atomic` root), not `home/.claude` (issue #150).
- [`atomic/internal/reminder/reminder.go`](../../atomic/internal/reminder/reminder.go) — file-based reminder CRUD. `remindersDir(repoRoot)` delegates to `config.RemindersDir(repoRoot)` — `<repoRoot>/<harness.dir>/.scratchpad/reminders`, default `.claude/.scratchpad/reminders`. `atomic reminder add|list|show|rm`.
- [`atomic/internal/followups/`](../../atomic/internal/followups) (16 files) — YAML-frontmatter follow-up parser, INDEX renderer, CLOSED.md append-only ledger, legacy migration. Implements `atomic followups list|add|close|render|migrate|path`. Anchors at git toplevel via `repoctx`. `cli.go`'s `Run` resolves the folder via `config.FollowupsDir(repoRoot)` (harness.go), not a private constant. Key functions: `LoadEntriesWithErrors` (parse boundary), `RenderIndex` (INDEX.md generation). `add` is the deterministic LLM-free entrypoint called by `/subagent-implementation` Phase 3 defer and `/subagent-diagnose`. `Kind` type (`KindFinding`/`KindPlan`) defined in `entry.go`; `parseKind` defaults empty string to `KindFinding` for back-compat. `AddOpts.Kind` defaults to `finding`; `--severity` is optional when `Kind=="plan"`. `isStale` returns false unconditionally for `KindPlan`. `Render` splits entries by kind before bucketing — plans to `writePlansBucket`, findings to severity buckets via `writeBucket`. `ListEntries --stale` excludes plans (via `isStale` returning false for them). Spec: [`docs/spec/typed-followups.md`](../../docs/spec/typed-followups.md).
- [`atomic/internal/prompt/prompt.go`](../../atomic/internal/prompt/prompt.go) — TTY abstraction over `github.com/charmbracelet/huh`. Exposes `Confirm` and `Select[T]`. Returns `ErrNonInteractive` (no TTY) and `ErrAborted` (Ctrl+C) as typed sentinels. All interactive prompts route through this package — direct `huh.*` calls outside `prompt/` are a convention violation. `doctor/stdin_prompter.go` adapts `prompt` errors to doctor's `Decision*` shape.
- [`atomic/internal/selfupdate/selfupdate.go`](../../atomic/internal/selfupdate/selfupdate.go) — GitHub Releases API lookup, SHA256-verified binary download, atomic replace via `os.Rename` with cross-filesystem fallback. Exposes `Client.Update` and `Client.Check`. Does NOT emit the out-of-sync nudge — that moved to `main.go:runUpdate`.
- [`atomic/cmd/atomic/main.go`](../../atomic/cmd/atomic/main.go) (`runUpdate`) — orchestrates the full update flow after binary swap: (1) re-execs the new binary as `<exe> claude update --no-update-check` (default; `--skip-claude-update` opts out) to refresh `~/.claude` artifacts — no detection gate, assumes update means refresh; (2) appends `--no-hooks` when `hooks.IsInstalled($HOME)` reports no session-start hook, so refresh never first-registers hooks; (3) fires post-update doctor after refresh. Re-exec is load-bearing: running process still embeds the OLD bundle after the swap. Refresh failure warns on stderr; never blocks update exit code. Helpers `detectManagedInstall`, `maybeRefreshArtifacts`, `resolveIfManagedGate` and `claudeinstall/managed.go` were removed; `--binary-only` was renamed to `--skip-claude-update`; the out-of-sync nudge is removed.
- [`atomic/internal/claudeinstall/install.go`](../../atomic/internal/claudeinstall/install.go) (`planArtifact`) — when `ActionMergeRequired` fires for CLAUDE.md (no parseable `<atomic>` block), the printed next-step message instructs the user to run `atomic prompt claude-merge` (not a slash command). `ProfileNudge` (printed by `ensureProfileStub` on first install) reads `Profile created at ~/.atomic/profile.md. ...` — swept from the pre-v6 path (issue #150).
- [`atomic/cmd/atomic/main.go`](../../atomic/cmd/atomic/main.go) — calls `config.MigrateUserState(home)` once, before any verb dispatches (best-effort: a failure prints one stderr warning and the invoked verb still runs). `runMigrateInstall(home)` performs the two-root split: config helpers (`config.TOMLPath`, etc.) receive `home` (the `~/.atomic` root), while `migrate.Context.Root` keeps its install-scope meaning of `<home>/.claude` — install-scope migration steps (`internal/migrate`) operate on the Claude artifact install target, not the atomic state root (D4 — Claude-integration paths stay hardcoded). Every other `config.*` caller in this file (`--target`, `runProfile`, list/diff verbs) was swept from a single shared `claudeHome`-style parameter to the same `home`/`filepath.Join(home, ".claude")` split.
- [`atomic/internal/repoinit/repoinit.go`](../../atomic/internal/repoinit/repoinit.go) — `Init(root string) ([]Action, error)` runs six idempotent layout guarantees, deriving all four repo-local target paths from `config.ScratchpadDir("")`, `config.ProjectDir("")`, `config.IndexDir("")`, `config.WorktreesDir("")` (harness.go) rather than hardcoded `.claude/...` literals — under the default `harness.dir`, the guarantees are: (1) [`.claude/.scratchpad/`](../../.claude/.scratchpad) dir exists, (2) [`.claude/project/`](../../.claude/project) dir exists, (3) [`.claude/.scratchpad/`](../../.claude/.scratchpad) ignored → append managed rule `/.scratchpad/` to the nested [`.claude/.gitignore`](../../.claude/.gitignore) (creating the file with a `# managed by atomic repo init; rules are relative to .claude/` header if it doesn't exist yet), (4) same pattern for [`.claude/.atomic-index/`](../../.claude/.atomic-index) → `/.atomic-index/` rule in the nested [`.claude/.gitignore`](../../.claude/.gitignore), (5) root `tmp/` ignored → `tmp/` rule in root [`.gitignore`](../../.gitignore) (no header — the only guarantee not nested under `harness.dir`), (6) `<harness.dir>/worktrees/` ignored → `/worktrees/` rule in the same nested [`.claude/.gitignore`](../../.claude/.gitignore) (moved off the root [`.gitignore`](../../.gitignore)'s `.worktrees/` rule — worktrees now live at `.claude/worktrees/<branch>/`, matching Claude Code's own default worktree path; `fix!: move worktrees to .claude/worktrees/`, pre-dates this branch, unrelated to issue #150). "Is it ignored" is answered by `git check-ignore -q` against a nonexistent probe path under the guarded directory; when git is unavailable or the answer is indeterminate, falls back to a literal line-scan of the target ignore file. Append-only — never rewrites, reorders, or removes existing gitignore content; never runs `git commit`. Each guarantee reports `Action{Name, Kind}` (`Kind` is `"created"` or `"ok"`). Invoked via the `atomic repo init` verb: [`atomic/cmd/atomic/main.go`](../../atomic/cmd/atomic/main.go)'s `buildRepoCmd`/`runRepo` resolve root via `repoctx.Resolve(repoOverride)`, call `repoinit.Init`, and print one `%-8s %s\n` line per action. Inherits the pre-existing `cli-repo-flag-never-parses` follow-up: the `init` leaf command's `DisableFlagParsing: true` means the root `--repo` flag is never parsed for this verb either.
- [`atomic/cmd/atomic/main.go`](../../atomic/cmd/atomic/main.go) (`buildTemplateCmd`/`templateAction`/`runTemplate`) — mirrors the `prompt` verb's shape: `buildTemplateCmd` builds a cobra parent `"template"` (Short: "Emit document skeletons (design-doc|spec|brief|state|followups|...)") plus one child subcommand per `doctemplate.Names()` entry, each with `DisableFlagParsing: true` and `Annotations: map[string]string{"args_hint": ""}`. `templateAction(args []string, out, errOut io.Writer) int` is the testable dispatch seam (same pattern as `promptAction`): no args → usage + valid names list, exit 1; unknown name → `doctemplate.Get` error, exit 1; known name → writes template text to `out`, exit 0. `runTemplate(args []string)` is the `os.Exit`-aware entry point. `rootCmd.AddCommand(buildTemplateCmd())` registers `template` as the 20th top-level verb — [`atomic/cmd/atomic/main_test.go`](../../atomic/cmd/atomic/main_test.go)'s `TestRootCmdExact20Verbs` gates the exact count (bumped from `repo`'s prior 19).

**State directory layout (`~/.atomic/` — moved from `~/.claude/.atomic/`, issue #150, v6):**

| Path | Contents |
|------|----------|
| `config.toml` | TOML user config (v1 schema) |
| `config.resolved.md` | Rendered markdown snapshot, `@`-ref'd from bundled [`CLAUDE.md`](../../CLAUDE.md) |
| `backups/<ts>/` | Files replaced during `atomic claude install/update` |
| `proposed/CLAUDE.md` | Proposed merge target when installed [`CLAUDE.md`](../../CLAUDE.md) diverges and no `<atomic>` block is parseable |
| `profile.md` | User profile stub written at install time by `atomic/internal/profile.RenderStub`. Sections: Identity (`<stable>`), Work (`<volatile>`), Active projects (`<volatile>`), Interests (`<stable>`), People mentioned (`<volatile>`), Environment (`<deterministic>`). |

**Follow-ups folder ([`.claude/project/followups/`](../followups)):**

Per-entry YAML-frontmatter `.md` files + auto-generated `INDEX.md` + append-only `CLOSED.md`. Frontmatter fields: `id`, `title`, `created`, `origin`, `kind` (`finding`|`plan`, default `finding` when absent), `severity` (required for findings, optional for plans), `review_by`, `status`, optional `file`. `INDEX.md` renders `## 📋 plans` section first (no staleness), then severity buckets for findings. Pre-commit hook stage 3 re-renders `INDEX.md` when followup entry files are staged.

## Coupling

- **→ doctor**: `checks_config.go` (doctor domain) imports [`atomic/internal/config`](../../atomic/internal/config) directly. Config schema changes must be reflected in `checks_config.go` validation. `checks_followups.go` imports [`atomic/internal/followups`](../../atomic/internal/followups) — follow-up schema changes affect doctor.
- **→ doctor**: `updatedoctor` reads `update.run_doctor` from config and is controlled by `--no-doctor` flag. Config schema change to that key requires updating `updatedoctor.go` logic.
- **→ bundle**: `claudeinstall.Apply` (bundle domain) pre-creates `config.resolved.md` on every install run. The content of that file is owned by [`atomic/internal/config/render.go`](../../atomic/internal/config/render.go) (this domain).
- **→ bundle**: [`atomic/internal/coldprompt/`](../../atomic/internal/coldprompt) briefs are embedded in the binary via `//go:embed`, NOT via the bundle mirror that ships [`agents/`](../../agents), [`commands/`](../../commands), [`skills/`](../../skills) to `~/.claude`. Adding a new brief requires editing `coldprompt.go`, not `bundlemirror/mirror.go`.
