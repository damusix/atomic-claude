# config

## What it does

User config, state directory, session hooks, reminders, follow-ups, and git state management. Everything that persists user preferences or project-local operational state across sessions. [`atomic/internal/config`](../../atomic/internal/config) also owns `RepoConfig.Scope` (GitHub issue #172) — a top-level `scope = "repo"|"realm"` key in [`.claude/atomic.toml`](../../.claude/atomic.toml) that declares a directory's own identity, resolved by the nearest-marker-of-the-requested-kind upward walk in [`scope.go`](../../atomic/internal/config/scope.go)'s `FindScopeRoot` and written idempotently by `EnsureScopeMarker`; [`atomic/internal/repoctx`](../../atomic/internal/repoctx) and [`atomic/internal/where`](../../atomic/internal/where) both consume it as the first-choice root-resolution mechanism, outranking `git rev-parse --show-toplevel` and the `<wikis>` registry respectively. [`atomic/internal/config`](../../atomic/internal/config) owns the TOML schema, including the `[claude.agents.<name>]` per-agent model+effort installer-override map (namespaced under a `claudeSection` on `Config.Claude` — [`agentoverride.go`](../../atomic/internal/config/agentoverride.go), [`agents.go`](../../atomic/internal/config/agents.go)) and a separate `[pi.agents.<name>]` schema for the Pi coding agent ([`pi_agent.go`](../../atomic/internal/config/pi_agent.go), resolved via `atomic config resolve`); both namespaces are opaque top-level TOML tables (`opaqueSections = {"claude", "pi"}`) and accept only nested tables — no flat/scalar entry form, no back-compat auto-migration; [`atomic/internal/followups`](../../atomic/internal/followups) owns the per-entry folder; [`atomic/internal/hooks`](../../atomic/internal/hooks) installs the session-start hook. Cold-op briefs for git cleanup and CLAUDE.md merge are embedded in the binary via [`atomic/internal/coldprompt`](../../atomic/internal/coldprompt) — they are NOT install artifacts and are never written to `~/.claude`. Per-user state root is `~/.atomic/` (GitHub issue #150, v6 breaking change — moved from `~/.claude/.atomic/`; see the state-directory-layout table below and [`docs/spec/configurable-state-paths.md`](../spec/configurable-state-paths.md)). Repo-local state paths — `.scratchpad/`, `project/` (followups), `.atomic-index/`, `atomic.toml`, `worktrees/` — resolve through one config key, `harness.dir` (string, default [`.claude`](../../.claude)), read once per process by [`atomic/internal/config/harness.go`](../../atomic/internal/config/harness.go)'s `harnessDir()` resolver; `atomic config set harness.dir .pi` repoints every repo-local helper to `.pi/...`. [`atomic/internal/config/repo.go`](../../atomic/internal/config/repo.go) owns a second, repo-scoped schema — `<projectRoot>/<harness.dir>/atomic.toml` (default `<projectRoot>/.claude/atomic.toml`), resolved via `config.RepoConfigPath` (harness.go) — distinct from the user-scoped `~/.atomic/config.toml` above: it is committed to the repo and currently holds only `[code] ignore` glob patterns consumed by the code-intel indexer (code-intel domain). This domain also owns repo-local [`.claude/`](../../.claude) layout scaffolding — [`.claude/.scratchpad/`](../../.claude/.scratchpad), [`.claude/project/`](../../.claude/project), [`.claude/worktrees/`](../../.claude), and the gitignore rules that keep them (plus root `tmp/`) out of version control — via the `atomic repo init` verb, implemented in [`atomic/internal/repoinit`](../../atomic/internal/repoinit) (all four repo-local paths now derive from the same `harness.go` helpers rather than hardcoded literals).

## Artifacts

**Follow-ups and git state:**

- [`commands/follow-up.md`](../../commands/follow-up.md) — `/follow-up [due <id> | review]`. Reviews pending follow-ups. `/follow-up review` triages stale [`.claude/project/followups/`](../followups) entries with per-item `extend|close|promote|skip`.

**Reminders and scheduling:**

- [`commands/remind-me.md`](../../commands/remind-me.md) — `/remind-me <duration> <text>` schedules reminder via cron. Degrades to file-only without `CronCreate`.
- [`commands/watch-ci.md`](../../commands/watch-ci.md) — `/watch-ci` dispatches `general-purpose` with `model: haiku` as a background subagent to watch CI. Provider auto-detected from signals or file-tree heuristics.

- [`atomic/internal/config/config.go`](../../atomic/internal/config/config.go) — TOML-backed user config. Load/validate/persist. v1 schema: `output.signals.max_depth` (int, default 3), `update.run_doctor` (bool, default `true`), `harness.dir` (string, default [`.claude`](../../.claude) — see `harnessDirDefault`). `output.intensity` was removed — the schema no longer contains it. Atomic write via `os.Rename`. Levenshtein typo-suggestion on unknown key names. Raw-map presence check distinguishes absent `update.run_doctor` (default `true`) from explicit `false`. `validateHarnessDir` rejects empty, [`.`](../..), [`..`](../../..), and any value containing [`/`](../..) on `Set`; `Load` re-applies the same check leniently (falls back to the default rather than erroring) so a hand-edited invalid value never reaches `filepath.Join` in the repo-local helpers. `Config.Claude.Agents` (a `claudeSection` embedded on `Config`, TOML key `claude`) is a `map[string]AgentOverride` — machine-written only (via `atomic config agents`), not part of `knownKeys`/user-settable via `atomic config set`. `Validate(cfg)` hard-fails on any `cfg.Claude.Agents[*].Effort` outside the 5-value enum; `model` is never a hard failure. `AgentWarnings(cfg)` returns non-fatal `Warning`s for an unknown agent name and for a malformed (non-`validModelFormat`) model value.
- [`atomic/internal/config/agentoverride.go`](../../atomic/internal/config/agentoverride.go) — `AgentOverride{Model, Effort string}`, the `[claude.agents.<name>]` entry shape. No custom `UnmarshalText`/`TextMarshaler` — nested tables are the only accepted shape; a scalar entry (e.g. a legacy flat `agents.x = "opus"`) is a config decode error, not a lenient fallback. `WritePersist` (`toml.Marshal`) emits nested `[claude.agents.<name>]` tables via the default struct-decode path. `validEfforts` is the strict 5-value enum (`low`, `medium`, `high`, `xhigh`, `max`); `validModelFormat` rejects only whitespace/control characters (lenient — any other string, including bare model ids like `claude-opus-4-8`, passes).
- [`atomic/internal/config/agents.go`](../../atomic/internal/config/agents.go) — `atomic config agents` interactive form: a `huh`-backed per-agent model `Input` + effort `Select` over the fixed `agentOrder` (5 bundled agents). `applyAgentOverrides(cfg, selections)` is the pure merge function — both fields empty removes the agent's `[claude.agents]` entry (falls back to bundled default); effort is validated against `validEfforts` (hard failure); model is never a hard failure. `AgentTierSelector`/`DefaultAgentTierSelector` is the injectable TTY seam; `ErrNonInteractiveAgents`/`ErrAgentsAborted` are the typed sentinels for a non-TTY session or a Ctrl+C abort.
- [`atomic/internal/config/pi_agent.go`](../../atomic/internal/config/pi_agent.go) — `ResolvePiAgents(globalPath, repoPath)` merges the global `~/.atomic/config.toml [pi.agents.<name>]` table with a repo-local `.pi/atomic.toml [pi.agents.<name>]` table (repo entries override per-field) into a `PiAgentResolveEnvelope{SchemaVersion, Valid, Agents, Diagnostics}`, validating agent names (`^[a-z0-9](?:[a-z0-9-]{0,62}[a-z0-9])?$`), `model` (non-empty `provider/model` shape), and `thinking` (`off|minimal|low|medium|high|xhigh|max`). A separate schema from the Claude Code `[claude.agents.<name>]` override above — distinct config namespace (`pi.agents`, renamed from `pi.agent` in the same CP7 commit that namespaced Claude's own table — a parser-key rename only, no pi agent-file writing), distinct fields (`model`+`thinking`, not `model`+`effort`), no installer patching. Envelope validity is two-tier: a source file that fails to parse, or whose `pi`/`pi.agents` table is the wrong shape, marks `Valid: false` for the whole envelope (both sources are still parsed and their diagnostics collected), while an individual invalid agent entry is dropped from the result map as a diagnostic without invalidating the rest; an invalid repo-side entry also removes that agent name from the global-sourced result before merging, so a broken repo override never silently falls back to a stale global one. `sortDiagnostics` orders diagnostics lexicographically (source/path/agent/code/message) for reproducible output. Consumed by `atomic config resolve --repo <root> --json` (`cli.go`).
- [`atomic/internal/config/cli.go`](../../atomic/internal/config/cli.go) — `atomic config get|set|unset|list|path|agents|resolve` subcommand dispatch. [`agents`](../../agents) runs the interactive form (`AgentTierSelector`) and applies selections via `applyAgentOverrides`; after `WritePersist` + `writeResolved` succeed, it calls the package-var seam `ApplyAgentsHook(home) (changed []string, installed int, err error)` — nil in production until [`atomic/cmd/atomic/main.go`](../../atomic/cmd/atomic/main.go) wires it at startup (this package cannot import [`atomic/internal/claudeinstall`](../../atomic/internal/claudeinstall) directly; that package already imports `config`, which would cycle). Outcome messaging: hook `nil` → "Agent tier overrides saved."; hook error → stderr `"...could not auto-apply..."` + `"Run 'atomic claude install' to apply."` but exit 0 (the config write itself succeeded); `installed == 0` → "No installed agents found — will apply on the next 'atomic claude install'."; `len(changed) == 0` → "Installed agents already up to date."; otherwise → prints the changed count + names and "Restart Claude Code sessions to pick up the change." `resolve --repo <root> --json` prints the merged Pi coding-agent overrides via `ResolvePiAgents` — both flags are required (`--json` is the only supported output mode; its absence is a usage error) and the command exits 1 when `env.Valid` is `false`, 0 otherwise.

- [`atomic/internal/config/repo.go`](../../atomic/internal/config/repo.go) — repo-scoped config parsing: `LoadRepoConfig(path)` (path now supplied by `harness.go`'s `RepoConfigPath(root)`, not a local const) into `RepoConfig{Code.Ignore []string; Scope string}` — `Scope` (`toml:"scope"`, issue #172) was added alongside the pre-existing `Code` table. Same lenient-load contract as `config.go`'s `Load`: missing file → empty config, no error; unknown keys → `Warning`, no error; malformed TOML → error the caller degrades on. `NewIgnoreMatcher(patterns)` builds an `IgnoreMatcher`: a pattern containing a slash character is a doublestar full-path match against repo-relative slash paths (`fullPath` field); a pattern without a slash matches the basename at any depth (`basenames` field); a leading dot-slash prefix is stripped; a trailing-slash-only pattern matches nothing; an invalid pattern (per `doublestar.ValidatePattern`) is dropped with a `Warning`, never panics; no negation syntax. `Match(relPath)` uses `doublestar.MatchUnvalidated` — patterns are pre-validated at construction, so re-validating per call is redundant. `PatternCount()` returns the number of active patterns, used by `atomic code status`. Depends on the `github.com/bmatcuk/doublestar/v4` module. `repoKnownSections` and `checkUnknownRepoKeys` both special-case a top-level `pi` key as opaque (skipped, no `Warning`) — the same treatment `config.go`'s `opaqueSections` gives it for the global schema. `checkUnknownRepoKeys` also treats `scope` as a known top-level **leaf** via the new `repoKnownTopLevelLeaves` set (distinct from `repoKnownSections`, which names tables, and `repoKnownLeaves`, which names dotted keys nested inside a known table) — without this, `scope` would warn as an unknown top-level key, since every other top-level key in this schema names a table.
- [`atomic/internal/config/scope.go`](../../atomic/internal/config/scope.go) (issue #172) — `ScopeSource` enumerates how a root was decided (`none`, `marker`, `git`, `registry`, `cwd`; `String()` renders the lowercase output token). `ValidScope(s)` reports whether `s` is `"repo"` or `"realm"`. `FindScopeRoot(startDir, scope)` walks from `startDir` (absolutized) upward to the filesystem root via repeated `LoadRepoConfig(RepoConfigPath(dir))` calls, returning the first directory whose config parses and whose `Scope` equals the requested kind; a missing file, parse error, invalid value, or the other kind all continue the walk — discovery never fails, it degrades, so the walk runs past `.git` boundaries (a realm root sits above its member repos). `EnsureScopeMarker(root, scope)` idempotently writes `scope = "<scope>"` as a top-level key: `ScopeMarkerCreated` (file didn't exist — written fresh), `ScopeMarkerAdded` (`insertTopLevelScope` finds the first table-header line at TOML bracket depth zero — via `bracketDelta`, which counts `[`/`]` outside quoted strings so an interior line of a multi-line array is never mistaken for a header — and splices the scope line immediately above it, using `dominantLineEnding` to match the file's existing CRLF/LF convention; appends at EOF when no table header exists), `ScopeMarkerOK` (key already matches — nothing written), `ScopeMarkerConflict` (key present with a different value — nothing written, caller surfaces the conflict). Every other byte of an existing file is preserved verbatim.
