# repl

## What it does

- `atomic repl` gives an agent a named, persistent Python or Node interpreter session it drives across separate Bash calls: `repl start` spawns a detached harness, `repl eval` runs code against it with interpreter state surviving between calls (separate OS processes), and `repl stop`/an idle timeout ends it (package doc, `atomic/internal/repl/protocol.go:1-6`).
- Each session is a detached `python3`/`node` child running an embedded harness script that serves its own unix socket; the Go side (`internal/repl` + the `repl` Cobra command) is a stateless spawner and client with no process of its own — killing [`atomic`](../../atomic) never kills a session.
- Exposes 6 CLI verbs — `start eval list status reset stop` — dispatched through `ReplAction` (`atomic/internal/repl/action.go:27-60`). Localhost/unix-only (macOS, Linux); no MCP exposure in v1 (non-goal, [`docs/spec/atomic-repl.md`](../spec/atomic-repl.md)).

## Coupling

- **config domain.** `[repl] idle_timeout` is a config-domain schema key at both scopes — `replSection` (`atomic/internal/config/repo.go:20-26`, shared shape decoded by both `RepoConfig.Repl` and the user-level `Config.Repl`) and `config.ValidateIdleTimeout` (must parse as a positive `time.Duration`; zero/negative is invalid, never "disable"). repl only consumes this via `action.go`'s `resolveIdleTimeout` (repo `config.LoadRepoConfig`/`config.RepoConfigPath` → user `config.Load`/`config.TOMLPath` → `DefaultIdleTimeout`) — the schema and its validation function live in config, not repl. `RootDir`/`SessionDir` also depend on `config.Dir(home)` for the `~/.atomic/repl` state root, same as bus's `~/.atomic` dependency.
- **config domain (scope resolution).** `resolveScopeRoots` (`action.go:74-92`) resolves the repo root via `repoctx.ResolveFrom(dir, repoOverride)` (`internal/repoctx`) and the enclosing realm root via `config.FindScopeRoot(realmSearchDir, "realm")` — both are config-domain primitives (the scope-marker walk), not repl-owned logic. A session's cross-repo visibility is entirely a function of how those two resolve.
- **config domain (verb count).** `buildReplCmd` in [`atomic/cmd/atomic/main.go`](../../atomic/cmd/atomic/main.go) registered `repl` as a new top-level Cobra command, bringing the total to 22; [`atomic/cmd/atomic/main_test.go`](../../atomic/cmd/atomic/main_test.go)'s `TestRootCmdExact22Verbs` gates the exact top-level verb list and must be updated whenever a verb is added, removed, or renamed anywhere in the binary.
- **doctor domain.** Both idle_timeout validation call sites live in doctor, not repl: [`atomic/internal/doctor/checks_repo_config.go`](../../atomic/internal/doctor/checks_repo_config.go) (category 13, repo-scoped — an invalid `[repl] idle_timeout` is folded into the existing WARN-only path, never FAIL, mirroring the `[code] ignore`/`scope` non-fatal-at-discovery-time contract) and [`atomic/internal/doctor/checks_config.go`](../../atomic/internal/doctor/checks_config.go) (category 9, user-scoped — an invalid `[repl] idle_timeout` fails `config.Validate` and is reported as FAIL, a stricter ceiling than the repo-scoped check). [`atomic/internal/cliusage/cliusage.go`](../../atomic/internal/cliusage/cliusage.go)'s 6 `{"repl", ...}` `Path` entries also feed the A1 artifact-citation lint (`atomic validate artifacts`) the same way bus's do.
- **bundle domain.** The `## Persistent REPL sessions` section in [`CLAUDE.md`](../../CLAUDE.md) and the `cli`-topic row in [`templates/commands/atomic-help.md`](../../templates/commands/atomic-help.md) (rendered to [`commands/atomic-help.md`](../../commands/atomic-help.md)) are bundle inputs — regenerating `make render`/`make bundle` after editing either keeps the embedded copy under [`atomic/internal/embedded/bundle/`](../../atomic/internal/embedded/bundle) in sync, per the mandatory artifact checklist. repl ships no `commands/*.md`, `agents/*.md`, or `skills/*/SKILL.md` — no slash command or skill was added for this feature, so there is no bundle-mirrored artifact file of its own.

## Conventions worth knowing

- The 8 exit codes are pinned literal values, never renumbered (`protocol.go:69-97`): `0` ok, `1` usage error, `2` session not found, `3` eval exception, `4` timeout, `5` session dead, `6` interpreter/environment unavailable, `7` protocol version mismatch. `list` is the one verb that always exits `0` regardless of dead entries in its output — it enumerates rather than targets a single session.
- A reaped (idle-timed-out) session and a name that was never `start`ed produce byte-identical not-found text, by design (`ErrSessionNotFound`'s doc, `client.go:18-22`; `notFoundError`, `action.go:239-241`) — the remedy is `atomic repl start` either way, so no marker distinguishes the two histories.
- `ScopeKey` hashes the cleaned scope root (SHA-256, first 12 hex chars) rather than embedding the path, specifically to bound the unix socket path under `maxSocketPathLen = 103` (`sun_path` is 104 bytes on macOS, 108 on Linux, NUL included) — an arbitrarily deep repo still produces a fixed-width session directory name (`paths.go:14-38`).
- `EnsureStarted` (`spawn.go:161-261`) takes the probe, stale-socket cleanup, and spawn under one `flock` (`acquireSessionLock`/`sessionLock.release`) — guarding only the spawn call would let two racing `start` calls both observe "dead" and both spawn, the second orphaning the first's process. A racer that loses the flock re-probes under it and reports already-running.
- `SpawnFunc` (`spawn.go:64`) is an injectable seam — production always passes `nil`, which `EnsureStarted` defaults to `DefaultSpawn` (a real interpreter); tests inject a stub so concurrency and failure paths are exercised without a real interpreter process, mirroring `codeintel/mcp/proxy.go`'s equivalent seam. `client.go`'s `SignalFunc`/`PidMatchFunc` are the same idea for the timeout escalation (no test waits on a real process or real wall-clock time).
- `MaxStreamBytes = 64 * 1024` caps `Response.Stdout` and `Response.Stderr` independently, and the harness — not the Go client — enforces it (`protocol.go:31-35`); a `repr`/`inspect` of a large value is capped on the same budget so one eval cannot hand back an arbitrarily large frame.
- The harness's working directory is always the resolved scope root (`SpawnSpec.ScopeRoot` → `cmd.Dir` in `DefaultSpawn`), never wherever `atomic repl start` happened to be invoked from — so relative paths in eval'd code resolve against the scope root consistently across every session.
- `ValidateName` (`paths.go:117-136`) rejects an empty name, a leading `-` (indistinguishable from a flag), a [`/`](../..)/`\` path separator, a null byte, or [`.`](../..)/[`..`](../../..) — deliberately mirroring [`atomic/internal/wiki/bucket.go`](../../atomic/internal/wiki/bucket.go)'s `validateBucketName`, since a session name becomes a filename the same way a bucket name does.
- File permissions are asserted, not incidental: session directories `0o700` (`spawn.go:187`, `meta.go:60`), socket and meta files `0o600` (`meta.go:77`, and both harnesses explicitly `chmod`/`umask` their bound socket to `0o600` — see `python_harness.py`'s `serve` and `node_harness.js`'s `serve`) — a session socket is code execution into a process that may hold `--env` secrets, so it is never left at the house `0o755`/`0o644` default.
- `Meta` deliberately carries no field for the `--env` values a session was started with (`meta.go:14-18`) — `list`/`status` render this struct directly, so there being nowhere to put a secret is a stronger guarantee than remembering to filter one out at render time.
- `materializeHarness` (`spawn.go:294-339`) unconditionally rewrites the on-disk harness script from the embedded bytes on every spawn, through temp-file-then-rename — the on-disk copy is treated as a cache of the binary's embedded bytes, never trusted stale, so an `atomic update` (new protocol/behavior) can't leave a harness on disk speaking the old one.
- The client-side eval timeout escalation (`client.go`'s `EvalOptions.escalate`) cross-checks the meta `PID` against `StartedAt` via `defaultPidMatch` (`ps -p <pid> -o etime=,state=`, rejecting zombie state `Z`) before sending any signal — a bare pid is a recycled-pid hazard by the time a long eval's deadline elapses, so nothing is ever signaled without first re-verifying process identity.
