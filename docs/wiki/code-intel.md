# code-intel

## What it does

Tree-sitter/wazero-based code-intelligence engine embedded in the [`atomic`](../../atomic) CLI. Parses source files into a SQLite-backed symbol graph, resolves cross-file references, and exposes the graph via the `atomic code` CLI verbs and an MCP server. Index lives at `<projectRoot>/<harness.dir>/.atomic-index/atomic.db` (default `<projectRoot>/.claude/.atomic-index/atomic.db`; `harness.dir` is a config-domain key, issue #150 — see [`atomic/internal/config/harness.go`](../../atomic/internal/config/harness.go)).

## CLI code

- [`atomic/internal/codeintel/cli/code.go`](../../atomic/internal/codeintel/cli/code.go) — `RunCode` dispatcher for `atomic code <verb>`: index, sync, status, search, callers, callees, impact, node, files, affected, explore, mcp. **Fixed in this range (GitHub issue #193, [`docs/spec/code-intel-surfaces.md`](../spec/code-intel-surfaces.md) 2026-08-10 change-log entry):** the internal `__serve` verb `DefaultSpawn` execs was never registered as a Cobra subcommand, so every real daemon auto-start spawn (`atomic code __serve --source ... --db ...`) failed at flag parsing with "unknown flag" before `RunDaemon` ever ran — invisible in-process because the checkpoint that introduced `__serve` drove `RunDaemon`/`RunProxy` directly in tests, never through the real command tree. `runServe` is deleted; `runMCP` gained a `--daemon` branch, so daemon mode is now `atomic code mcp --daemon --source <path> --db <path>` on the already-registered `mcp` verb. `mcp.DaemonArgv` is the single seam both `DefaultSpawn` and its regression tests build the argv through, so the two can no longer drift apart. [`atomic/internal/codeintel/mcp/binary_e2e_test.go`](../../atomic/internal/codeintel/mcp/binary_e2e_test.go) (new, 143 lines) is the regression test that would have caught this — it drives the real compiled binary as a subprocess, not `RunDaemon` in-process. `runIndex`/`runSync` print one combined stderr warning line (`atomic code index: repo config: <messages>`) when `Engine.IgnoreWarnings()` is non-empty (a degraded [`.claude/atomic.toml`](../../.claude/atomic.toml)); `runStatus` reports `Engine.IgnorePatternInfo()` — active ignore-pattern count + config path — in both human and JSON output (`StatusJSON.IgnorePatternCount`/`IgnoreConfigPath`, `omitempty` when zero). `EnsureGitignore(projectRoot)` appends `<harness.dir>/.atomic-index/` (via `config.IndexDir("")`, config domain — issue #150) to [`.gitignore`](../../.gitignore), not a [`.claude/.atomic-index/`](../../.claude/.atomic-index) literal.
- [`atomic/internal/codeintel/engine/engine.go`](../../atomic/internal/codeintel/engine/engine.go) — `Engine` facade (CP20): wraps db, pool, orchestrator, resolution pipeline, graph manager, searcher, and context builder. Both CLI and MCP compile against this. `GetAllNodes`/`GetAllEdges` are full-table-scan pass-throughs — one bulk read per request rather than per-node querying — added for the `serve` domain's full-graph code export ([`atomic/internal/serve/codegraph.go`](../../atomic/internal/serve/codegraph.go)'s `GET /code/graph/data` handler). `ensureIndexer` loads the repo-scoped ignore config ([`.claude/atomic.toml`](../../.claude/atomic.toml)) once per indexer boot via `config.LoadRepoConfig` + `config.NewIgnoreMatcher` (config domain), wiring the resulting `*config.IgnoreMatcher` onto the orchestrator via `SetIgnoreMatcher`; diagnostics (unknown keys, parse errors, invalid patterns) collect on `e.ignoreWarnings`, exposed via `IgnoreWarnings()`. `IgnorePatternInfo()` reports the active pattern count + config path without booting the indexer pool (a pool boot costs ~2GB peak RSS) — used by the read-only `atomic code status` path.

- [`atomic/internal/codeintel/extraction/extractor.go`](../../atomic/internal/codeintel/extraction/extractor.go) — `TreeSitterExtractor`: drives one file through the grammar, produces `ExtractionResult{Nodes, Edges, UnresolvedReferences}`. Appendix-E contract. `LanguageExtractor.FunctionScopeTypes` (optional set of grammar node-type strings that open a function scope without themselves being a `FunctionTypes` match, e.g. `arrow_function`) increments `visitor.scopeDepth` while `visitChildren` descends into a matching node; `extractSimpleNode`'s `VariableTypes` arm mints a node only at `scopeDepth == 0` AND when `isSingleIdentifierVariableName(name)` holds (rejects destructuring-pattern rendered text like `{ a, b }`) — either gate failing still walks `visitFunctionBody` so calls/JSX/field refs inside a suppressed initializer are harvested. Nil `FunctionScopeTypes` (Go, Python, …) leaves `scopeDepth` always 0, so minting behavior there is unchanged ([`docs/spec/code-intel-local-variable-suppression.md`](../spec/code-intel-local-variable-suppression.md)).
- [`atomic/internal/codeintel/extraction/languages/`](../../atomic/internal/codeintel/extraction/languages) — per-language `LanguageExtractor` configs: Go, TypeScript, TSX, JavaScript, Python, Ruby, Rust, Java, C, C++, C#, Swift, Kotlin, Dart, Lua, Luau, Objective-C, PHP, Pascal, Scala, plus a `registry.go`. `typescript.go`/`javascript.go` set `FunctionScopeTypes: extraction.TypeSet("arrow_function", "function_expression", "generator_function")` (grammar node-type strings confirmed by a real-parse probe, doc-commented in each file). Both files' `tsExtractImport`/`jsExtractImport` share `importNodeName(specifier)` (defined in `typescript.go`): a package-import specifier (not starting with [`.`](../..) or [`/`](../..)) keeps its full text as the import node's `name` (`@hapi/hapi`, `@langchain/core/messages` — previously collapsed to the last path segment, making same-named imports indistinguishable); a relative/absolute specifier still collapses to its basename (`./utils/context.ts` → `context.ts`).
- [`atomic/internal/codeintel/extraction/standalone/sql.go`](../../atomic/internal/codeintel/extraction/standalone/sql.go) — SQL language extractor (standalone; not tree-sitter-backed). Parses DDL/DML to extract table, view, procedure, trigger, and function nodes. **FK column-level references (iteration 2)**: `extractColumnFKRefs` scans a `CREATE TABLE` body for both table-level (`FOREIGN KEY (a[, b]) REFERENCES tgt (x[, y])`) and inline (`col TYPE REFERENCES tgt (x)`) FK clauses, emitting a `references` edge from the local column node (not the table node) to `tgt.col` when a target column list is given, or to the bare `tgt` table when it is omitted; `columnFKRefs` pairs local/target column lists positionally, additive to the pre-existing table→table edge (never dedups against it). Snowflake dialect: CREATE STAGE (A5), CREATE STREAM (A4), CREATE TASK with AFTER predecessor edges (A3), COPY INTO body-edge lineage including @stage sigil tokens, CLONE references, class/security preamble modifiers. dbt model extraction (B section): Jinja pre-pass harvests `ref()` / `source()` into a new `model` node and reference edges; placeholder-substituted residual SQL feeds the standard extractor. **v2 additions**: `CREATE FILE FORMAT` → `NodeKindFileFormat` (O1); VARIANT/OBJECT/ARRAY column typing (O2); `LATERAL FLATTEN(INPUT => tbl)` arg reference (O4); dbt macro definitions `{% macro … %}…{% endmacro %}` → `NodeKindMacro` nodes (E2); macro-body ref attribution — refs inside a macro span own the macro node (E3); project-path role detection (`/macros/` → macro-only, `/tests/`|`/analyses/` → no model node) (O9); versioned-ref distinct targets `__dbt_ref_<model>_v<N>` (O7); `config(alias=...)` stored in model node Metadata (O8); standalone top-level COPY INTO with lazy `NodeKindScript` owner (F4); Jinja `{# … #}` comment-leak fix (strip before harvest).

Returns `[]EmbeddedSpan` (mirrors `standalone.StringLiteralSpan` field-for-field; separate type to avoid import cycle).

- [`atomic/internal/codeintel/db/`](../../atomic/internal/codeintel/db) — SQLite layer: `db.go` enforces single-connection + 7-pragma appendix-O order; `schema.sql` embedded via `go:embed`; CRUD, migrations, stats, search, resolution helpers. `tx.go`'s `Tx.NodeExists(ctx, id) (bool, error)` checks whether a node id exists within the current transaction (`SELECT 1 FROM nodes WHERE id = ? LIMIT 1`) — used by `indexer/orchestrator.go`'s unresolved-ref owner guard to verify a ref's owner node before insert. - [`atomic/internal/codeintel/resolution/resolver.go`](../../atomic/internal/codeintel/resolution/resolver.go) — `Resolver.ResolveImport(ctx, ref)`: classifies one import-kind `UnresolvedReference` as Internal/External/Unresolved. Specifier normalization runs before alias expansion / external classification / relative resolution: for JS-family languages (`isJSFamily` — JS, JSX, TS, TSX) `stripQueryAndFragment` cuts a trailing `?query` and/or `#fragment` (browser-ESM cache-busting, e.g. `./editor.js?v=2026.07.23.1`) at the first `?`/`#` occurrence — but only when that occurrence is not the first character, so a `#`-led Node.js [`package.json`](../../package.json) `"imports"`-field subpath specifier (`#internal/config`) is left intact. `isExternal` classifies JS-family specifiers by Node resolution semantics — any specifier not starting with [`.`](../..), [`/`](../..), or `#` is external (covers scoped packages, bare packages, and package subpaths like `date-fns/format` in one rule; the prior hardcoded `nodeBuiltins` allowlist and its `!strings.Contains(specifier, "/")` bare-name rule were removed) — plus a language-agnostic `"://"` substring check for URL-scheme specifiers (`https://cdn…/+esm`), checked ahead of the per-language branches. `ResolvedImport.PackageName` is set (JS-family External verdicts only) via `npmPackageName(specifier)`: `""` for a `://` specifier; the specifier verbatim for a `node:`-prefixed one; the first two slash-segments for an `@`-scoped one; otherwise the first slash-segment (bare specifiers pass through unchanged).
- [`atomic/internal/codeintel/indexer/orchestrator.go`](../../atomic/internal/codeintel/indexer/orchestrator.go) — `Orchestrator`: `IndexAll`, `IndexPaths`, `Sync` — walks project files, dispatches to pool, persists results. `IndexAll` and `Sync` share a `scanAndIndex` body: `checkExtractorVersion` reads `project_metadata`'s `extractor_version` key (bumped by hand — currently `"2"`, function-scoped local-variable suppression) and reports `(forceFull, needStamp)`; a mismatch (or an unstamped pre-existing index with file rows) forces one full re-extraction pass (`indexFiles`'s new `forceReindex` parameter bypasses the content-hash dedup skip in `indexOneFile` for every file), stamped via `stampExtractorVersion` only after the run completes successfully — a crash mid-migration leaves the mismatch in place so the next run retries rather than recording a migration that never finished. `IndexAll` and `Sync` call `pruneDeleted` after indexing to remove rows for files that no longer exist on disk. `compoundExt` helper extracts `.sql.jinja` as a compound suffix (stdlib `filepath.Ext` returns `.jinja` for compound extensions). `storeExtractionResult` guards unresolved-ref inserts with an owner check: if a ref's `FromNodeID` is absent from the file's own `result.Nodes`, it calls `Tx.NodeExists` against the DB; only when the owner is absent from both is the ref skipped (recorded in the file's `errors` column) instead of failing the whole file's transaction on the `unresolved_refs.from_node_id` FOREIGN KEY. Test coverage: [`atomic/internal/codeintel/indexer/orchestrator_dangling_ref_internal_test.go`](../../atomic/internal/codeintel/indexer/orchestrator_dangling_ref_internal_test.go). `SetIgnoreMatcher(*config.IgnoreMatcher)` configures a repo-scoped ignore filter (nil disables filtering, the default); `filterIgnored` is the single discovery-time filtering seam shared by `IndexAll`, `Sync`, `IndexPaths`, and `ScanFiles` — `IndexAll`/`Sync` feed the same filtered list to both `indexFiles` and `pruneDeleted`, so a newly-ignored file is reclaimed as an orphan by the existing prune mechanism with no separate ignore-prune step. `ScanFiles` was reshaped from a free function to an `Orchestrator` method so `engine.ExtractFrameworkNodes` sees the identically-filtered file set `IndexAll`/`Sync` produce, rather than a second unfiltered scan that could silently diverge.
- [`atomic/internal/codeintel/indexer/embedded_sql_postpass.go`](../../atomic/internal/codeintel/indexer/embedded_sql_postpass.go) — CP2: orchestrator post-pass. After host tree-sitter extraction, harvests string literals, gates via `IsSQLLiteral`, resolves owner host node, calls `ExtractEmbeddedSQL`, merges into `ExtractionResult`. Controlled by `embeddedSQLHostExts` registry. **sql-string-match (C1)**: for each literal that fails `IsSQLLiteral`, emits an `UnresolvedReference{ReferenceKind: types.ReferenceKindSQLString}` when the literal matches an identifier shape (`^[A-Za-z_][A-Za-z0-9_]{2,}(\.[A-Za-z_][A-Za-z0-9_]+)?$`), the host file is non-SQL, and the (owner, literal) pair is not a dedupe repeat; `FromNodeID` from the existing `findOwnerNode` span match, `ReferenceName` = literal verbatim. **CP5 (C8 fragment tier)**: when a literal fails both `IsSQLLiteral` and the C1 identifier-shape regex, `embeddedSQLPostPass` falls through to [`atomic/internal/codeintel/indexer/sql_fragment_harvest.go`](../../atomic/internal/codeintel/indexer/sql_fragment_harvest.go)'s `emitSpeculativeSQLFragmentRefs` — a separate `sqlFragmentSeen` dedupe map (`ownerID+"\x00"+token`, distinct from `sqlStringSeen` so a fragment token and a same-text `sql_string` literal from the same owner never collide) keyed per file.
- [`atomic/internal/codeintel/indexer/sql_fragment_harvest.go`](../../atomic/internal/codeintel/indexer/sql_fragment_harvest.go) — CP5: C8 fragment-tier harvest for builder-arg SQL fragments (ActiveRecord `where("title LIKE ?")`, GORM `Where("name = ?")`, `order("created_at DESC")`, comma lists like `select("isbn, out_of_print")`) that fail both C1's identifier shape and `IsSQLLiteral`. `matchesSQLFragmentGate` requires: length ≤ `fragmentMaxLen` (160 chars), at least one identifier-shaped token (`fragmentTokenRE`), and at least one discriminator — a comma, a bare `?`, a comparison operator (`fragmentComparisonRE`: `<> != <= >= = < >`), a bind placeholder (`fragmentPlaceholderRE`: `$N` or `:name`), or a connective keyword (`fragmentConnectiveRE`: `ASC|DESC|LIKE|IN|IS|AND|OR|NOT|NULL|BETWEEN`, case-insensitive). `tokenizeSQLFragment` extracts surviving tokens after dropping a 27-entry case-insensitive `fragmentStoplist` (the connectives plus `select/from/where/order/group/by/having/limit/offset/join/on/as/distinct/case/when/then/else/end`). One `UnresolvedReference{ReferenceKind: types.ReferenceKindSQLFragment}` is emitted per surviving token via `emitSpeculativeSQLFragmentRefs`.
- [`atomic/internal/codeintel/resolution/sql_string_match.go`](../../atomic/internal/codeintel/resolution/sql_string_match.go) — sql-string-match resolution: pass A (C2) matches dotless `sql_string`/`sql_fragment` refs against SQL `table`/`view`/`procedure`/`function` node names via one bulk fetch per kind loaded into an in-memory lowercase-name map (never a per-ref DB round trip); confidence `high` when the ref's `CalleeExpr` is in the C4 query-builder vocabulary, else `medium`; >3 exact-name candidates → no edges (ref deleted), 2–3 → edge to each. Returns the owner→anchor map (`FromNodeID` → matched table/view nodes) pass B consumes. Pass B (C3) resolves columns only: qualified `x.y` refs match `x` against the same table/view candidates then `y` against `QualifiedName` (`medium`); bare refs match against the columns of the owner's pass-A anchors only (`low`) — unanchored bare columns never emit edges. **C8 fragment demotion**: `resolveSQLStringRefs` fetches both `ReferenceKindSQLString` and `ReferenceKindSQLFragment` refs via two `GetUnresolvedRefsByKind` calls and runs them through the identical passes A/B; every tier `sql_fragment` refs compute is then passed through `demoteConfidence` (`high`→`medium`, `medium`→`low`, `low` stays `low`) before the edge is built, at both the pass-A object-name site and both pass-B column sites (qualified and anchored-bare). C5 cleanup deletes every remaining `sql_string`/`sql_fragment` ref after both passes — zero rows of either kind persist regardless of match outcome. All edges created with `Kind: references`, `Provenance: "string-match"`, confidence in `Edge.Metadata`.
- [`atomic/internal/codeintel/extraction/standalone/query_builder_vocab.go`](../../atomic/internal/codeintel/extraction/standalone/query_builder_vocab.go) — C4: `QueryBuilderCallees`, a flat 28-name lowercase set of query-builder/ORM entry points (`selectfrom`, `insertinto`, `updatetable`, `deletefrom`, `replaceinto`, `mergeinto`, `from`, `into`, `table`, `join`, `innerjoin`, `leftjoin`, `rightjoin`, `fulljoin`, `crossjoin`, `joinraw`, `call`, `callproc`, `from_`, `table_`, `column`, `field`, `tablename`, `withtablename`, `totable`, `hascolumnname`, `hastablename`, `entityname` — Kysely/Knex-style plus 8 declaration-DSL callees (`column`, `field`, `tablename`, `withtablename`, `totable`, `hascolumnname`, `hastablename`, `entityname`) added alongside the C8 fragment-tier work); `IsQueryBuilderCallee` does the case-insensitive lookup. Membership only upgrades confidence medium→high in pass A — never causes an edge on its own.
- [`atomic/internal/codeintel/indexer/embedded_literals_config.go`](../../atomic/internal/codeintel/indexer/embedded_literals_config.go) — authoritative per-language `EmbeddedLiteralConfig` table for the 16 new host languages (C, C++, C#, Java, JavaScript, Kotlin, Lua, Luau, Objective-C, Pascal, PHP, Ruby, Rust, Scala, Swift, Dart). Node kinds probed from live wazero/tree-sitter grammars — do not alter without re-probing. See `docs/spec/embedded-sql-language-expansion.md § Grammar node-kind config`.

- [`atomic/internal/codeintel/indexer/typescript_harvester.go`](../../atomic/internal/codeintel/indexer/typescript_harvester.go) — CP4 (indexer adapter): adapts `HarvestTypeScriptLiterals` to `literalHarvester` for `.ts` and `.tsx` files.
- [`atomic/internal/codeintel/resolution/pipeline.go`](../../atomic/internal/codeintel/resolution/pipeline.go) — three-phase resolution pipeline (warm cache → name-match → synthesis); `ResolveAndPersistBatched` with optional `PhaseEmitFunc` profiling hook. The standard per-ref batch loop explicitly skips any ref with `ReferenceKind == types.ReferenceKindSQLString || ReferenceKind == types.ReferenceKindSQLFragment` (both left untouched — not deleted, not resolved), then a Phase 4 calls `resolveSQLStringRefs` (in `sql_string_match.go`) after standard resolution completes, running passes A/B/cleanup (C2–C5) over both ref kinds together. `resolveOne` Step 6 (`matchReference`) is skipped entirely for import-kind refs (`importKind`) — an import node is named the raw specifier string, and an unresolved import ref's `ReferenceName` is that same specifier, so generic exact-name matching would resolve the ref back to the import node that owns it (a self-loop edge); import refs resolve only via Steps 3–5, or are skipped with no edge. Step 5 (`ResolveImport`): an `External` verdict with a non-empty `PackageName` returns `extraction.GenerateNodeID("", "package", ri.PackageName, 0)` directly, bypassing the `targetKind` probe (a `GetNode` on a not-yet-minted package id would fatally abort the batch). **Package-node mint + sweep (CP2)**: `warmKnownPackages` loads existing `package`-kind node ids once per resolve run (mutated in place as new packages mint, so a package discovered in batch N is not re-minted in batch N+1); per batch, any edge targeting an unknown package id (via `packageNameFromNodeID`, prefix-matched against `packageNodeIDPrefix = "package:npm/"`) gets its `newPackageNode` upserted before the edge inside the same transaction (FK order), deduped within the batch too; `sweepOrphanPackages` runs once after all batches commit, deleting any `package` node with zero inbound edges (its last importer was removed since minting).

## Conventions worth knowing

- **Branding hard rule**: the reference TypeScript engine's product name must never appear in code, comments, identifiers, strings, tool names, or output. Brand slug = [`atomic`](../../atomic); MCP tools = `atomic_code_*`; data dir = [`.claude/.atomic-index/`](../../.atomic-index).
- **Engine lifecycle**: `New` → (`Init` or `Open`) → use → `Close`. `Init` is idempotent; `Open` errors if index absent. All facade methods call `requireDB()` first.
- **Single-connection SQLite**: `SetMaxOpenConns(1)` + `SetMaxIdleConns(1)` enforced in `db/db.go`. Appendix-O pragma order is mandatory — `busy_timeout` first.
- **Extraction is best-effort**: errors are recorded in `ExtractionResult.Errors`, never abort. Unresolved calls emit `UnresolvedReference` (not edges); edges are created only after resolution.
- **Store-time owner guard on unresolved refs**: distinct from extraction-time best-effort above — `storeExtractionResult` (orchestrator) guards the *storage* step. `unresolved_refs.from_node_id` has a `FOREIGN KEY REFERENCES nodes(id)`; a ref whose owner node was never added to `result.Nodes` (an extractor bug — e.g. attributed to a node the extractor later strips) would otherwise FK-fail the whole file's transaction, which bubbles up through `indexFiles` → `IndexAll` and skips the resolution phase for the entire run. The guard checks `Tx.NodeExists` against the DB before failing; if the owner is absent from both the file's own nodes and the DB, the ref is skipped and the skip is recorded in the file's `errors` column (fail loud, not silent) instead of aborting the transaction.
- **Framework extraction ordering**: `ExtractFrameworkNodes` must run after `IndexAll`/`Sync` and before `ResolveReferences` so route→handler refs exist when the resolution pipeline runs.
- **Deleted-file pruning**: `pruneDeleted` (orchestrator) runs after every `IndexAll` and `Sync`. Builds an O(1) set of on-disk relative paths, queries `GetAllFiles`, then for each absent file runs one `WithTx` that calls `Tx.DeleteNodesByFile` (FK-cascade removes edges) + `Tx.DeleteUnresolvedRefsByFile` + `Tx.DeleteFile`. `IndexPaths` does NOT prune — it receives an explicit subset and would wrongly delete every out-of-subset file.
- **`engine.NewWithDBPath(projectRoot, dbPath)`**: overrides the default index-path convention to an explicit db path. Used by the MCP daemon for cwd-independent operation (`atomic --repo <path> code mcp`); a realm member daemon receives the realm db path directly so it never needs to resolve from cwd.
- **Watch stubbed in v1**: `Watch`/`StopWatch` return `ErrWatchNotImplemented` per appendix M.
- **SQL extractor is standalone**: `extraction/standalone/sql.go` does not use tree-sitter; it has its own parse logic. Reused verbatim by `embedded_sql.go` for DDL literals. Taxonomy: 39 `NodeKind` values (31 → 35 after Snowflake/dbt v1; 35 → 38 after v2; v2 T-SQL gaps add no new kinds; 38 → 39 for `package`, 2026-08-08). The seven SQL-dialect kinds: `stage`, `stream`, `task`, `model`, `file_format`, `macro`, `script`. `TestNodeKindCount` in `types/types_test.go` asserts the exact count (currently 39) — update when adding node kinds.
- **Local-variable suppression (extraction)**: a `VariableTypes` match mints a node only at `scopeDepth == 0` (module/class/namespace scope) AND when the resolved name is a single identifier, not a destructuring pattern's rendered text (`{ a, b }`, `[c, d]`). `FunctionScopeTypes` is wired for TypeScript, TSX, and JavaScript only (arrow/function-expression/generator-function bodies); languages without it (Go, Python, …) are byte-identical to pre-change output. `for (const x of y)` bindings are unaffected by construction (a bare `identifier` statement field, never wrapped in a `lexical_declaration`); `namespace N { const X }` and Vue/Svelte `<script setup>` top-level `const` are kept (not function scopes).
- **`extractor_version` self-healing migration**: `project_metadata.extractor_version` (currently `"2"`) is bumped by hand whenever an `extraction/` change would produce different nodes/edges/refs for already-indexed, on-disk-unchanged files — the content-hash dedup skip would otherwise hide the semantic drift forever. `atomic code index` and `atomic code sync` both check it via `checkExtractorVersion`; a mismatch forces one full re-extraction pass, stamped only after the run completes successfully so a crashed migration retries on the next run rather than recording a false success.
- **Package nodes for external imports**: a JS-family (TS/TSX/JS/JSX) `External` import verdict with a derivable npm package name resolves to a shared `package:npm/<name>` node via an `imports` edge — every importer of `@hapi/hapi` converges on one hub instead of each import node being an orphan. Minted lazily in the resolution batch loop (never by extraction), tracked so an unchanged run re-fires no FTS triggers, and swept when a package's last importer is removed. Scoped to JS-family/npm only — Go, Python, and Rust imports are unaffected; a URL-scheme specifier (`https://…`) never mints a package. `atomic code callers "<pkg>"` returns the importing nodes correctly; the CLI `callees` name-lookup surface additionally unions same-named import nodes (followup `cli-callers-name-collision-package-imports`) — the graph-level hub itself has out-degree 0.
- **Import-resolution robustness fixes (2026-08-08)**: `ResolveImport` strips a trailing `?query`/`#fragment` from JS-family specifiers before classification (browser-ESM cache-busting), except when the specifier starts with `#` (a Node.js [`package.json`](../../package.json) `"imports"`-field subpath). `isExternal` for JS-family languages now follows Node resolution semantics uniformly (any specifier not starting with [`.`](../..), [`/`](../..), or `#` is external) instead of a hardcoded builtin-name allowlist, closing gaps for bare-subpath packages (`date-fns/format`) and `#`-prefixed subpaths; a language-agnostic `"://"` substring check classifies URL-scheme specifiers (CDN/remote ESM imports) as external ahead of the per-language branches. Import-kind refs never fall through to generic exact-name matching in `resolveOne` (Step 6 skipped) — an import node is named its own specifier, so that fallback previously produced self-loop edges.
- **T-SQL lineage gaps v2 (proc-scoped temp tables, OUTPUT INTO, PIVOT, column-level)**: `sql.go` gains four capabilities. (1) Temp tables/table variables: `CREATE TABLE #tmp` / `SELECT … INTO #tmp` / `DECLARE @t TABLE(…)` emit `writes`+`references` edges to a synthetic routine-scoped node whose `Name` encodes the routine and whose `Metadata` carries `{"temp":"local"|"local_tvar"|"global"}` and the written token; scalar `DECLARE @id INT` emits nothing; global `##g` is file-level deduped. (2) `INSERT/UPDATE/DELETE/MERGE … OUTPUT <list> INTO <target>` emits a `writes` edge to `<target>`; match is bounded by output-list char class so a statement boundary prevents a false cross-statement match; `OUTPUT` without `INTO` emits no edge. (3) `PIVOT`/`UNPIVOT`: source `references` edge preserved via FROM clause; no edge to PIVOT/aggregate/IN-list values (confirmed no-op; test committed). (4) Column-level 4a: alias→table map built from FROM/JOIN clause; qualified `alias.col` emits a `references` edge to the column node (`acct.id` → `acct.id`); unqualified refs skipped. Two SQL-scoped resolver tweaks in `resolution/name_matcher.go`: (a) single-dot SQL ref routes to `byQualifiedName` (not bare-name lookup); (b) `byQualifiedName` prefers an exact full-QName candidate over partial matches. Pipeline pre-filter fix in `resolution/pipeline.go`: `hasAnyPossibleMatch` adds an SQL-scoped simple-name fallback so qualified column refs (`dbo.Account.account_id`) are not dropped before reaching `byQualifiedName`.
- **Resolver tweak SQL scope gate**: all three resolution changes (`name_matcher.go` tweak-a/b, `pipeline.go` pre-filter fallback) are gated on `ref.Language == LanguageSQL` — non-SQL `receiver.method` resolution is unchanged; existing cross-language resolution tests stay green.
- **Snowflake / dbt conventions**: `modPat` in `sql.go` absorbs `OR REPLACE` / `OR ALTER` / `IF NOT EXISTS` — do not re-add these in new regex patterns. dbt `ref('pkg','model')` has the package as the **first** positional; a bare 2nd string literal is the model name only when 2 positionals are supplied. Version is always a keyword arg (`v=`/`version=`), never positional. Project-path role (`dbtFileRole`): path segment `/macros/` → `"macro"` (no model node, harvest macro defs); `/tests/`|`/analyses/`|`/seeds/`|`/snapshots/` → `"other"` (no model node); all other paths → `"model"`. Macro-body attribution: refs inside `{% macro %}…{% endmacro %}` byte spans own the macro node (E3) — checked via `inMacroSpan` linear search (dbt does not support nested macros). Jinja `{# … #}` block comments stripped (`dbtJinjaCommentRE`) before harvest so comment-embedded refs are not extracted. `config(alias=...)` stored as JSON in model node `Metadata` field. Standalone top-level `COPY INTO` outside a dbt context creates a `NodeKindScript` owner named `<file-basename>` (lazy — created on first COPY found in file).
- **`.sql.jinja` compound-extension routing**: `filepath.Ext` returns `.jinja` for `stg.sql.jinja`, which would route to unknown. `compoundExt` helper in `orchestrator.go` checks `HasSuffix(".sql.jinja")` before falling through to `filepath.Ext`. `exts.go:SQLExtensions` includes `.sql.jinja` so the admission guard and extension map agree.
- **Embedded SQL pipeline**: `embeddedSQLPostPass` (orchestrator post-pass) → per-language literal harvester → `IsSQLLiteral` gate → `ExtractEmbeddedSQL` → merge into `ExtractionResult`. Hosts: Go (hand-written scanner), Python (tree-sitter, docstrings excluded), TypeScript/TSX (tree-sitter, template-literal interpolations substituted); **16 additional languages** via the generic `HarvestEmbeddedLiterals` harvester (C, C++, C#, Java, JavaScript, Kotlin, Lua, Luau, Objective-C, Pascal, PHP, Ruby, Rust, Scala, Swift, Dart) driven by per-language `EmbeddedLiteralConfig` in `indexer/embedded_literals_config.go`. Two extraction shapes: Shape 1 (content-child grammars — `string_content`-style children) and Shape 2 (inline-content grammars — take node's own text, splice `"?"` over interpolation byte ranges, strip delimiter-alphabet prefix/suffix). All embedded edges carry `Provenance:"embedded"` (queryable via `GetEdgesByProvenance("embedded")`). Standalone `.sql`/`.ddl`/`.pgsql`/`.mysql` routing is unchanged. Host-ext set derived from `extToLanguage` + config table (single source, not a second hand-maintained ext list).
- **Admission gate `IsSQLLiteral`**: canonical implementation in `standalone/embedded_sql.go`; recognizes SQL structure only (no stopword lists); multi-fragment / concatenated queries are accepted false negatives.
- **Eval harness extended**: [`scripts/code-eval/embedded-sql-eval.sh`](../../scripts/code-eval/embedded-sql-eval.sh) and [`atomic/cmd/embedded-sql-admission/`](../../atomic/cmd/embedded-sql-admission) support gate-accuracy evaluation. `embedded-sql-admission` scans a directory tree and reports admitted literals (exit 0 = success, exit 1 = usage/IO error).
- **Tool gating**: MCP server registers only 3 tools when `fileCount < 500` (`atomic_code_explore`, `atomic_code_search`, `atomic_code_node`).
- **SQL string-match extraction**: never mints nodes. A host-language string literal that looks identifier-shaped (`^[A-Za-z_][A-Za-z0-9_]{2,}(\.[A-Za-z_][A-Za-z0-9_]+)?$`, ≤1 dot) but fails the embedded-SQL `IsSQLLiteral` gate becomes a speculative `sql_string`-kind `UnresolvedReference` (C1), matched post-resolution against already-indexed SQL table/view/procedure/function names (pass A, C2) and, for anchored owners, column names (pass B, C3). Ambiguity cap: >3 exact-name candidates → no edge. Confidence tiers (`high`/`medium`/`low`) live in `Edge.Metadata`; `high` requires the ref's `CalleeExpr` to be in the C4 `QueryBuilderCallees` vocabulary (28 names). Every `sql_string` ref is deleted after both passes (C5) — re-index/sync is idempotent, no row accumulation. Resulting edges carry `Kind: references`, `Provenance: "string-match"` and are ordinary edges in `callers`/`callees`/`impact`/graph output. **C8 fragment tier**: a literal that fails both C1's identifier shape and `IsSQLLiteral` gets one more chance — the fragment gate (`sql_fragment_harvest.go`: ≤160 chars, ≥1 identifier token, ≥1 discriminator — comparison operator, placeholder, comma, or connective keyword) tokenizes it into a keyword-stoplist-filtered token set, each surviving token becoming a `sql_fragment`-kind `UnresolvedReference`. `sql_fragment` refs run through the identical passes A/B as `sql_string`, then have their computed confidence demoted one notch (`high`→`medium`, `medium`→`low`, `low` floor) to offset the higher prose-collision risk of tokenizing free text; C5 cleanup now deletes both kinds.
- **Repo-scoped ignore (graphignore)**: [`.claude/atomic.toml`](../../.claude/atomic.toml) `[code] ignore = [...]` excludes matching files from indexer discovery. No negation syntax; v1 is exclude-only. A file that becomes newly ignored is pruned from an existing index by the *same* `pruneDeleted` mechanism (Deleted-file pruning convention above) — it simply drops out of the discovery list `filterIgnored` produces, so there is no second ignore-specific prune path. A degraded config (malformed TOML, invalid glob, unknown key) never fails indexing — it degrades to unfiltered/partially-filtered with a stderr warning. This repo dogfoods it: [`.claude/atomic.toml`](../../.claude/atomic.toml) ignores `atomic/internal/serve/assets/vendor/**` (~3.8k vendor symbols excluded from the code graph).
