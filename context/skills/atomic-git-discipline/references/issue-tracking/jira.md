# Jira issue tracking

Operations for `issue-tracker: jira`, which covers Jira Cloud sites at `<site>.atlassian.net`. Jira calls an issue a work item. If `jira` looks like the wrong tracker, see `../resolution.md`.

The CLI is `acli`, the Atlassian CLI. Its rows use the account `acli jira auth login` signed in. Rows it does not cover give the REST call to `https://<site>.atlassian.net/rest/api/3` with `--user "<atlassian-email>:$JIRA_API_TOKEN"`. The `acli` docs do not show `acli jira auth status` printing the site or email, so an interactive caller asks the user for `<site>` and `<atlassian-email>` before a REST row. On a path that cannot ask, such as the follow-up sink, skip `label-list` and `label-apply`. Run `issue-create` without `--label`, write the severity and kind into the description, and report each label as skipped. Jira labels are site-wide free text, and the docs do not say whether `--label` creates a label it does not find. Jira is unusable there only when `auth-check` fails or the project is ambiguous.

`issue-tracker-project` is the Jira project key, the prefix of every work item key (`ACME` in `ACME-42`). When it is unset, run `acli jira project list --json --paginate`. If the account reaches exactly one project, use it. If it reaches several, an interactive caller asks the user which one; the follow-up sink treats the project as ambiguous, records through `filesystem`, and reports why. Either way, suggest `atomic workflow set issue-tracker-project <KEY> --level repo`.

## Operations

| Operation | How | Source |
|-----------|-----|--------|
| `auth-check` | `acli jira auth status`. When `acli` is absent, the check fails. Treat a nonzero exit as a failed check; the page documents no output or exit status, so that signal is `unverified`. To sign in, pipe the token on stdin: `printf '%s' "$JIRA_API_TOKEN" \| acli jira auth login --site "<site>.atlassian.net" --email "<atlassian-email>" --token`. | https://developer.atlassian.com/cloud/acli/reference/commands/jira-auth-status/, https://developer.atlassian.com/cloud/acli/reference/commands/jira-auth-login/, https://developer.atlassian.com/cloud/acli/guides/install-acli/ |
| `issue-create` | `acli jira workitem create --project "<KEY>" --type "Task" --summary "<title>" --description-file <file> --label "<a>,<b>" --json`. The description file takes plain text or Atlassian Document Format. Use a work item type the project offers. | https://developer.atlassian.com/cloud/acli/reference/commands/jira-workitem-create/ |
| `issue-view` | `acli jira workitem view <KEY>-<n> --json`. Add `--fields "summary,status,labels,description"` to narrow the result. | https://developer.atlassian.com/cloud/acli/reference/commands/jira-workitem-view/ |
| `issue-search` | `acli jira workitem search --jql 'project = <KEY> AND text ~ "<query>"' --json`. `text ~` searches every text field, comments included. | https://developer.atlassian.com/cloud/acli/reference/commands/jira-workitem-search/, https://support.atlassian.com/jira-software-cloud/docs/jql-fields/ |
| `issue-close` | `acli jira workitem transition --key "<KEY>-<n>" --status "Done" --yes`. The status name comes from the project's workflow, so read the current one with `issue-view` and use the project's closing status. | https://developer.atlassian.com/cloud/acli/reference/commands/jira-workitem-transition/ |
| `label-list` | `unsupported` as a CLI. REST: `GET /rest/api/3/label?maxResults=1000`, paging with `startAt`. Labels are site-wide, not per project. | https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-labels/ |
| `label-apply` | `--label` on `issue-create`. For an existing work item, `unsupported` as a CLI, since the `acli` docs do not say whether `--labels` adds or replaces. REST: `PUT /rest/api/3/issue/<KEY>-<n>` with `{"update":{"labels":[{"add":"<name>"}]}}`, which keeps the other labels. Apply only labels `label-list` reports. On the path that cannot run `label-list`, apply none, as described above. | https://developer.atlassian.com/cloud/acli/reference/commands/jira-workitem-create/, https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-issues/ |
| `template-location` | `unsupported`: Jira has no issue-template file. `acli jira workitem create --generate-json` writes a work item definition that `--from-json <file>` reads back, which can serve as one kept in the repository. | https://developer.atlassian.com/cloud/acli/reference/commands/jira-workitem-create/ |
| `commit-reference-syntax` | The work item key anywhere in the message, for example `ACME-42`. Smart Commits add commands after the key: `ACME-42 #comment <text>`, `ACME-42 #time 2h`, and `ACME-42 #<transition-name>`, for example `#close`. A Smart Commit command cannot span lines. Smart Commits need the repository host linked to Jira and Smart Commits turned on, and the committer email must match a Jira user. | https://support.atlassian.com/jira-software-cloud/docs/process-issues-with-smart-commits/ |
| `project-identifier` | The project key, for example `ACME`. `issue-tracker-project`, when set, is this value; pass it as `--project` and in `project = <KEY>` JQL. | https://developer.atlassian.com/cloud/acli/reference/commands/jira-project-list/, https://developer.atlassian.com/cloud/acli/reference/commands/jira-workitem-create/ |

## Gotchas

- Authentication is an Atlassian API token in `JIRA_API_TOKEN`, used with the account email. Keep it in the variable and never print its value. Source: https://developer.atlassian.com/cloud/jira/platform/basic-auth-for-rest-apis/
- An API token can carry scopes. A scoped token calls `https://api.atlassian.com/ex/jira/<cloud-id>` instead of the site URL. New tokens expire after one year at most. Source: https://support.atlassian.com/atlassian-account/docs/manage-api-tokens-for-your-atlassian-account/
- Rate limits combine an hourly quota, per-second burst limits per endpoint, and per-issue write limits. Any of them returns HTTP 429; wait for the `Retry-After` header before retrying. Source: https://developer.atlassian.com/cloud/jira/platform/rate-limiting/
- Never create a label. Report every label you skipped, whether `label-list` did not list it or could not run because the site or email was unknown.
