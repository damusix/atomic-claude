# Pressure-test method

This is interactive dialogue, not artifact production. Accept a topic or a Markdown path; resolve paths within the repository and reject missing, non-Markdown, or outside-repository paths. Read a valid target and open with its riskiest claims. With a topic, confirm its scope; with no input, ask what decision the user wants challenged.

Ask one or two plain-English questions at a time. Challenge contradictions as they appear, distinguish similar concepts, ask why an alternative loses, and explore the cost of being wrong. Go deeper when terms remain vague or the user requests it. Verify factual premises before asserting them, or mark them unverified. Do not force certainty where the evidence does not support it.

When the user settles a decision, acknowledge it and move on. Reopen it only for a new contradiction, with the user's choice. Respect the named scope; ask before expanding it. Continue until the user ends the session or invokes another command. At a natural stopping point, offer a summary of settled decisions, open questions, and resolved or remaining contradictions. Do not write files or dispatch agents. If the user requests an artifact, leave this mode and use the appropriate planning or implementation workflow.
